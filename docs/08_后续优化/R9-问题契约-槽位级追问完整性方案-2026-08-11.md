## 1. 背景与问题定义

### 1.1 真实场景

```
悬壶助手：患者咳嗽是干咳还是有痰，痰的颜色和量怎么样？
医师：有痰
（然后 agent 就跳过了，没有继续追问痰的颜色和量）
```

这是一个**单问题内部回答不完整**的场景：一个问题里包含多个子问（有无痰 / 痰的颜色 / 痰的量），患者只回答了第一个子问，agent 就视为"呼吸维度已覆盖"，转向其他维度。

### 1.2 根因分析（两个层次）

| 层次 | 机制 | 覆盖情况 |
|---|---|---|
| 维度级 | R1 图内循环：整个问诊维度不完整时，下一轮继续问该维度 | ✅ 已有 |
| **问题级** | **单个问题内部的回答完整度循环**（子问漏答 → 稳定补问） | ❌ **无** |

现状：`present_illness.sputum = 有痰` 这个粗粒度事实一旦落账，完整性判定就认为呼吸维度"已覆盖"。后续是否补问痰色、痰量完全依赖模型的自觉（prompt 里有"尽量追问"，但不是稳定行为）。

### 1.3 为什么不能只靠 prompt 修

模型"更可能追问"≠"必然追问"。追问是否发生取决于上下文长度、模型状态、prompt 措辞。要保证稳定性，必须把"答不完的追问"从**模型自觉**变成**系统强制**。这正是 R9 问题契约机制的目标。

### 2.3 已确认的三个边界（本方案要解决的）

1. **规划边界**：契约 aspects 由模型当时规划。若第一问契约只写了 1 个 aspect（"有无痰"），答"有痰"后契约 satisfied，痰色痰量**永远不会出现在残余里**，照样被跳过。
2. **语义边界**：程序只验证"引文真实存在"，不验证"引文确实回答了该方面"。模型可把 quote="痰"（真实存在于"有痰"里）当作"痰的颜色"的 evidence，span 校验通过，契约判 satisfied。
3. **时滞边界**：有 cap（默认 2 次追问）。持续不答则 disposition 变 `EXHAUSTED_PARTIAL` 推进；之后患者主动说"痰是白的"，只进 observation 事实账本，**不回填已关闭契约**，账本与事实脱节。

### 4.2 层 2：规划层维度 Rubric（解决"该问什么"）

**目标**：契约 aspects 不再完全依赖模型当时规划，系统对每个维度**首次提问**冻结必含的方面集合。

#### 4.2.1 数据模型（配置化，版本化）

```python
# app/agent_runtime/question_rubric.py（新文件，纯常量 + schema 版本号）
# 与 QUESTION_TEMPLATES 同风格：Python 版本化常量，不是数据库字段，不是 per-dimension 代码分支

class RubricAspect(BaseModel):
    criterion: str                        # 与契约 aspect criterion 同格式（陈述句、无问号）
    required: bool                        # 恒必填
    conditional: tuple[str, ...] = ()     # 条件：如 ("cough.productive=true",) 有痰时必填
    safety_derived: bool = False          # 是否为安全项（由确定性安全规则求值，不归 Rubric 管）

RESPIRATORY_RUBRIC_V1 = DimensionRubric(
    version="respiratory.v1",
    dimension="ten_questions.respiratory",
    aspects=(
        RubricAspect(criterion="说明咳嗽是否有痰（干咳/有痰）", required=True),
        RubricAspect(criterion="说明痰的颜色", required=False,
                     conditional=("present_illness.sputum=有痰",)),
        RubricAspect(criterion="说明痰的量", required=False,
                     conditional=("present_illness.sputum=有痰",)),
        RubricAspect(criterion="说明痰的质地（稀/黏/泡沫等）", required=False,
                     conditional=("present_illness.sputum=有痰",)),
    ),
)

QUESTION_RUBRICS: dict[InquiryDimension, DimensionRubric] = {
    InquiryDimension.TEN_RESPIRATORY: RESPIRATORY_RUBRIC_V1,
    # 其余维度按需补齐；未配置的维度走"模型自由 aspects + 1 个通用兜底"（现状行为）
}
```

**不膨胀原则**：Rubric 是配置数据不是 schema 字段；新增维度只加一个 `DimensionRubric` 常量，不动状态结构、Reducer、数据库。

#### 4.2.2 契约生成算法（与模型 aspects 合并）

```python
def plan_contract_aspects(
    dimension: InquiryDimension,
    model_aspects: tuple[QuestionAspectDraft, ...],
    current_facts: Sequence[ActiveObservationContext],
) -> tuple[str, ...]:
    rubric = QUESTION_RUBRICS.get(dimension)
    if rubric is None:
        return tuple(item.criterion for item in model_aspects) or (f"补全 {dimension.value} 当前问题所需信息",)
    # 1) 条件必填求值：有痰 → 痰色/痰量/痰质进入必答集合
    required_criteria = [a.criterion for a in rubric.aspects if a.required]
    for a in rubric.aspects:
        if a.conditional and _condition_holds(a.conditional, current_facts):
            required_criteria.append(a.criterion)
    # 2) 模型 aspects 与 Rubric 并集（去重），Rubric 项优先、保持顺序
    merged = list(required_criteria)
    for m in model_aspects:
        if m.criterion not in merged:
            merged.append(m.criterion)
    # 3) 有痰但痰相关尚未冻结：把条件必填项补入（防止"有痰→契约只含咳嗽性质"的退化）
    if _has_fact(current_facts, "present_illness.sputum=有痰"):
        for a in rubric.aspects:
            if a.conditional and a.criterion not in merged:
                merged.append(a.criterion)
    return tuple(merged[:4])   # 契约上限 4 个 aspects
```

关键点：**条件求值发生在"回答后"**。首次提问时患者未答，契约冻结的是 Rubric 完整子问集合（咳嗽性质 + 痰色 + 痰量 + 痰质）；患者答"有痰"后，覆盖判定将痰色/痰量/痰质标为 `unanswered`（答"干咳"则标 `not_applicable`）→ 残余追问自动出现。这从规划层根除"有痰只问一次就跳过"。

#### 4.2.3 覆盖判定中的条件语义

- 答"干咳" → 痰相关 aspects 由判定为 `not_applicable` → `_SATISFYING_STATUSES` 满足 → 契约 satisfied，不追问；
- 答"有痰" → 痰相关 `unanswered` → 残余 → 追问；
- 无痰/有痰判定错误 → 层 3 语义校验兜底（4.3）。

### 4.3 层 3：语义充分性校验（解决"答没答到位"）

**问题**：span 真实 ≠ 回答到位。模型可把 quote="痰" 挂到"痰的颜色"名下，契约误判 satisfied。

#### 4.3.1 轻量关联校验

在 `build_coverage_event` / `_verify_coverage_binding` 之上新增一个**纯函数校验**（新文件 `app/agent_runtime/coverage_semantics.py` 或并入 `question_contract.py`）：

```python
def validate_aspect_semantics(
    aspect: QuestionAspect,
    evidence_text: str,          # 当前回答 span 原文
) -> CoverageStatus:
    """返回建议状态；仅当判定足够确信时才降级，否则原样返回。"""
    hints = _SEMANTIC_HINTS.get(_criterion_key(aspect.criterion))   # 配置化小词表
    if hints is None:
        return None             # 无词表 → 不干预（默信模型）
    if not hints.required_terms:
        return None
    if any(term in evidence_text for term in hints.required_terms):
        return None             # 命中关键词 → 维持 addressed
    return CoverageStatus.UNCLEAR   # 未命中 → 降级，留在残余里继续问
```

示例词表（配置化，随评测迭代）：

```python
_SEMANTIC_HINTS = {
    "痰的颜色": _Hint(required_terms=("白", "黄", "绿", "红", "褐", "透明", "咖啡", "脓", "血")),
    "痰的量":   _Hint(required_terms=("多", "少", "大量", "少量", "中等", "一", "两口", "毫升")),
    "咳嗽性质": _Hint(required_terms=("干咳", "有痰", "咳痰", "无痰", "没痰")),
}
```

#### 4.3.2 降级策略（不误伤）

- **降级路径**：`addressed` → `unclear`（留在残余追问），**不 reject**。`unclear` 不满足契约 → 自然进入下一轮残余，避免"判定过严导致合法回答被拒、整轮丢失"。
- **仅当模型判为 `addressed`/`not_applicable` 时才干预**；`unanswered`/`unclear`/`unavailable` 原样放行。
- `not_applicable` 的干预：答"干咳" → 痰相关 `not_applicable` 命中 `required_terms`（"干咳"）→ 维持；答"有痰"却判痰色 `not_applicable` → 词表命中"有痰"但语义相反，走 `unclear`。
- 校验结果进入覆盖事件前做**程序校正**（不是仅提示）：`build_coverage_event` 接受"校正后状态"，证据引文不变。

#### 4.3.3 与既有机制的关系

- **不替代 grounding**（span 真实性）——层 3 是它的补充；
- **不扩大拒绝面**：现有失败码集合（`_INTAKE_RETRYABLE_MODEL_CODES` / `_INTAKE_SILENT_DEGRADE_CODES`）不变，语义降级走"覆盖状态"，不产生新的 intake 失败。

### 4.4 层 4：cap 到顶后的晚来信息策略（解决"账本与事实脱节"）

**场景**：契约到 cap 关闭（`EXHAUSTED_PARTIAL`）后，患者说"痰是白的、量少"。

**决策（MVP 与进阶两级）**：

**MVP（推荐先做）**：契约账本**不回填**，但保证两件事：
1. 晚来信息正常作为 observation 吸收（现有机制已满足，`sputum.color=white` 落事实账本）；
2. 完整性判定**不因"契约已关闭 + 事实已补"而重复追问**：`project_contract_dimensions` 把已关闭契约的维度放进 `contract_resolved_dimensions`，`covered.update(...)` 已实现 → 不再问；
3. 患者重新提及同一维度时，若已有该维度事实，`_recent_question_turns` / 主诉重提走既有去重逻辑。

**进阶（账本同步，可选增强）**：新增**修订覆盖事件**（`coverage_amendment`）：
- 晚来消息（新 `answer_message_id`）绑定到已关闭契约的残余 aspect；
- 表结构：`coverage_amendments(id, root_contract_id, contract_id, aspect_id, answer_message_id, evidence, digest)`，折叠时并入 `evidence_by_aspect` / `source_event_ids`；
- 效果：账本反映"痰色最终由第二条消息补全"，`event_count`/`followups_used` 语义不变；
- **代价**：fold 复杂度上升（修订与链上事件的次序）、幂等键需扩展。建议 R9-D 之后再评估，不进 MVP。

### 4.5 层 5：交互措辞兜底（不依赖模型临场发挥）

- 残余追问模板（系统级，`_template_result` 已支持带 `frozen_residual_aspects`）：
  ```
  已了解{已满足项}。请补充{残余项}。
  # 例：已了解患者有痰。请补充痰的颜色、痰的量、痰的质地。
  ```
- 模板命中时 `source=TEMPLATE`，零模型请求，稳定且不漂移；
- 模型路径下，prompt 强制"冻结残余原样回传 + 只能追问这些项"（`question_composer_v2.jinja2` 已写）；

#### D3：脱敏与校验不同源

**位置**：`app/agents/intake_extraction.py:112`（`project_model_input_identity_sequences`）与各 grounding/coverage 校验器

**问题**：模型看到 `█`，校验对质原文数字，必然不匹配。

**修复（推荐方案：等长掩码通配）**：

```python
def _span_quote_matches(content: str, start: int, end: int, quote: str) -> bool:
    raw = content[start:end]
    if raw == quote:
        return True
    # 等长掩码：quote 中的 '█' 通配 raw 中任意字符
    return len(raw) == len(quote) and all(
        q == "█" or r == q for r, q in zip(raw, quote)
    )
```

- 等长替换保证偏移一致，只需在 `build_coverage_event` / `_verify_coverage_binding` / `intake_grounding` 共用同一匹配函数（抽公共工具，避免三处实现漂移）；
- EvidenceRef 存 `quote_sha256`：需改为对**原文子串**取摘要（校验通过后取 `raw` 的摘要），保证取证可复验；
- 新增测试：患者回答含电话号码且 evidence 引用跨越该区间 → 通过且摘要对应原文。

### 5.2 契约生命周期

```
[root contract, rev=1] ──答──▶ [coverage event] ──残余非空──▶ [follow-up rev=2] ──答──▶ ...
                                    │                              │
                                    ▼ (无残余)                      ▼ (revision-1 == max_followups)
                                SATISFIED                    OPEN 或 (EXHAUSTED_PARTIAL / MANUAL_REQUIRED)
                                                                     ▲ 安全契约 → MANUAL_REQUIRED（转人工）
                                                                     └ 非安全契约 → EXHAUSTED_PARTIAL（部分推进）
```

### 5.3 边界条件

| 情形 | 行为 |
|---|---|
| 无契约路径（legacy） | `contract_reply_context=None`，intake 不产 coverage，completeness 投影全空 → 现网行为完全不变 |
| 患者答"不知道" | `unavailable` → 不满足契约 → 仍在残余；cap 到顶后 `EXHAUSTED_PARTIAL`。**与设计意图"不重复追问不知道"的偏差已接受**（有界，不致死循环）；如需完全对齐，进阶可让 `unavailable` 在 fold 中从残余剔除（在 `evaluate_contract_coverage` 的 `unresolved` 计算处排除 `UNAVAILABLE` 状态项） |
| 答"干咳" | 痰相关 `not_applicable` → satisfied，不再追问 |
| 重放同一回答 | `event_id = uuid5(contract_id, answer_message_id)` 相同 → 追加式合并 byte-equal no-op |
| 刷新/重启 | 契约/事件从 PostgreSQL 恢复，digest 重验，fold 重算 |
| 模型改写残余 aspects | `MODEL_OUTPUT_INVALID` → 模板兜底，残余不被模型重规划 |
| 安全维度 | 不投影到 contract 维度（schema 拒绝）；安全采集状态仍以 `SafetyProfile.collection_status` 为准 |

## 10. 风险与边界（明确不做的事）

1. **语义校验是"轻量防线"不是"医学判定"**：词表匹配可能误伤边缘表达（如"痰色正常""没有特别颜色"）。设计为降级（`unclear`）而非拒绝 + 词表随评测迭代 + 可开关。
2. **"不知道"仍会被追问至 cap**：与设计意图（记录后不再问）有偏差，但**有界**（cap 兜底，不致死循环）。完全对齐需 fold 改动（`unresolved` 计算剔除 `UNAVAILABLE`），列为可选增强。
3. **契约固化的是规划时的目标**：Rubric 已补全"首次提问冻结子问集合"，但**会话中途新出现的主诉/症状**仍靠既有 gap selector 处理（新维度 → 新契约），不属于本方案。
4. **`coverage_amendments`（账本回填）不进 MVP**：MVP 用"observation 吸收 + resolved 投影防重问"满足场景；账本级同步留待评估。
5. **模型"答非所问但引文真实"**：层 3 降低误判率，不能 100% 消除（医学表达开放）；语义词表覆盖不足时维持模型判定（默信）。
