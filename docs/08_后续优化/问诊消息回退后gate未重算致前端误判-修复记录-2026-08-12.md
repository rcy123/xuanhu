> 关联真实会话：`4292b0b4-b917-4394-926b-6c108eaf0f3f`（回退后无法继续回答）
> 关联提交：`4b3b4f5`（fix(rollback)）、`919e265`（fix(intake)）、`628d397`（feat(rollback)）
> 关联文档：`问诊同维度细化回答误判冲突致停滞-优化记录-2026-08-12.md`（同域问题链）

---

## 1. 问题概述

用户在问诊中途做**两次消息回退**（撤销 4 条回答，恢复到"每晚大概能睡几个小时？"的提问），
回退成功后**无法继续回答**：界面提示"当前流程需要恢复"，输入被禁用。

**会话操作还原（4292b0b4，审计事件）：**

| 时间 | 操作 | 结果 |
|---|---|---|
| 15:14:02 | 提交消息 | intake 判定 **stagnated** → 会话 blocked |
| 15:14:35 | 恢复当前阶段（recover） | inquiry，state_version 19→20 |
| 15:14:41 | 回退 #1（撤销 2 条） | state_version 21 |
| 15:14:46 | 回退 #2（撤销 2 条） | state_version 22，保留"每晚睡几个小时"提问 |

回退后：`current_stage=inquiry`、`status=active`、`recovery_status=normal`，状态本身正常，
但前端 `langGraphDisposition` 返回 `manual_required`，输入框被禁用。

---

## 2. 根因分析

### 2.1 代码路径

```
回退删除消息/事实（observations / safety / contracts）
  → state_version +1（=22）
  → ❌ 未重算 completeness gate
读模型 _authoritative_intake_gates：选 input_state_version 最大的 gate
  → 旧 completeness gate（ver=19，disposition=stagnated）仍被投影
前端 langGraphDisposition：
  completenessDisposition === 'stagnated' → 返回 'manual_required'
  → LangGraphAdvanceBar 显示"当前流程需要恢复"
  → intakeReady=false / canSubmit 相关判定受 stale gate 影响
  → 用户无法继续回答
```

### 2.2 缺陷本质

`gate_results` 是**追加式历史记录**，回退不会自动产生新 gate。读模型按"最新版本"投影，
旧 gate（其 `input_state_version` 落后于回退后的 `state_version`）被当作权威：

- 若旧 gate 是 `stagnated` → 前端误判"需恢复"（本次案例）
- 若旧 gate 是 `ready` → 前端误判"问诊已完整"→ 禁用输入提示进入辨证（同类缺陷）

同时读模型的 `unresolved`（missing_required）也基于旧 gate，与回退后的真实事实不符。

---

## 3. 修复方案

**回退后重算 completeness gate**：用剩余事实重新评估，写入一条
`input_state_version = 回退后版本` 的新 gate，使读模型投影真实完整性。

### 3.1 重算逻辑（`app/services/message_rollback.py::_recompute_intake_gates`）

1. **剩余 observations**：加载全部（含修正链），投影为 `ObservationSchema`（链头即当前真相）；
2. **safety profile**：映射为 `SafetyProfileSchema`（回退已重置受影响字段为 unknown）；
3. **triage 保守沿用**：取最近一条 triage gate 的 details 重建（disposition/risk_level），
   红旗状态**不因回退被重估放宽**——回退只撤销对话，不改变已确认的风险判定；
4. **completeness 重算**：构造 `CompletenessPolicyInput`（`_completeness_snapshot` +
   triage gate + 重置 progress），`evaluate_completeness_policy` 得到真实 disposition；
5. **持久化**：新建一条 `completed` graph_run（`command_id=rollback:*`）+ 写入
   triage / completeness 两条 GateResult（`input_state_version = 回退后版本`）。

### 3.2 为什么不用其他方案

| 备选方案 | 否决原因 |
|---|---|
| 读模型过滤 `input_state_version != 当前版本` 的 gate | safety 确认会 `state_version+1`，导致正常流程 gate 失效、advance 找不到匹配版本 → 破坏既有行为 |
| 删除/失效旧 gate | 破坏追加式审计语义 |
| 前端判断回退标记 | 只掩盖表象，读模型 unresolved 仍错误 |

## 4. 效果验证

**真实会话 4292b0b4（用新代码重算后）：**

| 指标 | 修复前 | 修复后 |
|---|---|---|
| completeness gate | `blocked / ver=19 / stagnated` | `failed / ver=22 / incomplete` |
| triage gate | `passed / ver=19` | `passed / ver=22`（沿用 details） |
| unresolved | 旧 missing（基于 stagnated gate） | 真实缺失：四诊、安全维度、胸腹、头身、呼吸、汗、口渴等 |
| 前端行为 | "当前流程需要恢复"、输入禁用 | "请补充上方未收集信息后继续"、**可正常回答** |

**测试**：新增 1 例集成测试（回退后新 gate 版本/关联 graph_run/disposition），
回退测试 7/7 通过；全量回归 **3235 passed, 0 failed**。

---

## 5. 边界与后续

- **progress 重置**：回退后 progress 归零（重新计数），避免回退前的停滞计数延续；
- **红旗沿用**：triage 沿用最近一次判定，若红旗来自被回退删除的消息，需在后续轮次
  由新的 triage 重估——当前保守策略不会误放行；
- **同类风险**：任何"状态回退但 gate 不重算"的操作（如未来新增的修改方回退）应复用
  `_recompute_intake_gates` 或等效逻辑。
