## 1. 问题概述

真实会话中，医生对同一枚举维度（冷热）**逐步细化**回答，被系统误判为"值冲突"全部丢弃，
连续 2 轮无新事实后触发问诊停滞（`intake_stagnated_manual_required`），会话被自动阻断，
UI 提示"当前流程需要恢复"。

**会话对话还原（d5df99f0，按提交顺序）：**

| 轮次 | agent 提问（维度） | 医生回答 | 提取结果 |
|---|---|---|---|
| 1 | 症状变化情况 | 主要是时好时坏，但整体比之前加重了… | ✅ 新事实 2 条 |
| 2 | 冷热总体倾向 | 胃部非常怕冷，不敢吃凉的 | ✅ 存为 active（cold_heat） |
| 3 | 其他部位冷热 | 平时手脚也容易发凉，整体体质偏怕冷 | ❌ 0 条（值冲突被丢弃） |
| 4 | 冷热总体倾向 | 总体倾向是怕冷 | ❌ 0 条（值冲突被丢弃）→ 停滞 |

三条回答都是**"怕冷"主题下的兼容信息**（局部怕冷 → 手脚也凉 → 总体怕冷），逐步细化补充，
**没有一条是矛盾信息**（如"怕热"），却全被当作冲突丢弃，最终触发停滞。

---

## 2. 根因分析

### 2.1 代码路径

```
提取器输出 cold_heat ADD delta（value=自由文本）
  → _drop_value_conflicting_adds（app/services/langgraph_intake.py）
      同 key 已有 active（"胃部非常怕冷"）
      _delta_value_key(new) ≠ _observation_value_key(active)   ← 只做字面 JSON 比较
      → 一律判"冲突" → 丢弃（reason=value_conflicts_active_fact）
  → new_fact_count = 0
  → _next_progress: no_new_facts_rounds + 1
  → 第 4 轮同样 → no_new_facts_rounds = 2
  → _stagnation（app/agent_runtime/completeness_policy.py）
      no_new_facts_rounds ≥ 阈值(2) → stagnated → manual_required → blocked
```

### 2.2 两个缺陷

1. **值冲突判定过于激进**：`_drop_value_conflicting_adds` 只做字面 JSON 字符串比较，
   `"胃部非常怕冷"` ≠ `"总体倾向是怕冷"` 一律当冲突丢弃。它必须激进，是因为下游 reducer
   对同 key 多 active 值会抛 `OBSERVATION_SOURCE_CONFLICT` 整轮失败（append-only 模型
   不允许一维两值）。结果：**细化信息丢失 + 停滞误触发**。

2. **停滞语义过宽**：`_stagnation` 只要 `no_new_facts_rounds ≥ 2` 就停滞，不区分
   "还有必需维度缺失但无进展"（真空转，应防呆）与"所有必需维度已覆盖后的确认轮"
   （对话在收敛，不应阻断）。本案中 cold_heat 早已 covered，医生在确认/细化已覆盖维度，
   仍被判定空转。

## 3. 方案设计

### 3.1 核心：同维度兼容值合并（三分类判定）

把 `_drop_value_conflicting_adds` 从"字面不同即丢弃"升级为**语义三分类**：

```
同 key 不同字面值的 ADD：
├─ 语义兼容（同向细化/确认） → 转换为 CORRECT 观察
│     值 = 旧值 + 新文本，supersedes 旧链头（复用 append-only 修正链）
├─ 语义矛盾（怕冷 vs 怕热）  → 丢弃（保留现有行为，防事实矛盾）
└─ 无法判定（维度未覆盖/非文本/触发词未命中） → 保守丢弃
```

**为何复用 CORRECT 修正链而非直接 UPDATE**：
- observations 是 append-only（可追溯、幂等），直接改值破坏审计；
- CORRECT 链式追加完全符合现有领域模型（reducer 已支持，投影层取链头即为合并后完整文本）；
- 零 schema 变更，reducer/projection/completeness 的"一维一值"假设不变。

**语义判定实现**（`_semantic_value_relation`，纯规则、无模型调用）：
- 可枚举维度规范化键表（`_ENUM_DIMENSION_NORMALIZERS`）：cold_heat / sweat / sleep / thirst / appetite
- 触发词子串匹配 + **否定前缀保护**（"不怎么想喝水"不命中"想喝水"）
- 两值命中同向键 → compatible；互斥键 → conflict；未命中/非文本 → unknown

### 3.2 配套：停滞语义修正

`_stagnation` 增加 `missing_required` 判定：
- **必需维度全部覆盖（missing_required 为空）** → 无新事实的确认轮不构成空转 → 不停滞（正常收尾 READY）
- **仍有必需维度缺失且连续无进展** → 停滞防护照常生效（防呆保留）

## 4. 实施详情

### 4.1 `app/services/langgraph_intake.py`

新增：
- `_ENUM_DIMENSION_NORMALIZERS`：5 个枚举维度的规范化键表
- `_semantic_keys_of`：触发词子串匹配 + 否定前缀保护
- `_semantic_value_relation`：三分类判定（compatible / conflict / unknown）
- `_merge_observation_texts`：文本合并（追加/去重包含关系）

改造：
- `_drop_value_conflicting_adds`：维护 active 观察对象（含 id）；同 key 不同字面值时三分类——
  compatible → 构造 CORRECT delta（value=合并文本，target=active 链头）；conflict / unknown →
  丢弃并留痕（reason 细分 `value_conflicts_active_fact` / `value_incompatible_unknown`）

### 4.2 `app/agent_runtime/completeness_policy.py`

改造：
- `_stagnation` 增加 `missing_required` 参数；`reasons` 非空但 `missing_required` 为空时清空
  （不停滞）；调用处 `evaluate_completeness_policy` 传入 `missing_required`

## 6. 效果（本案模拟）

| 轮次 | 旧行为 | 新行为 |
|---|---|---|
| 3（手脚也凉） | 丢弃 → no_new_facts=1 | 合并为 CORRECT（值=两段合并）→ new_facts=1 → 计数归零 |
| 4（总体怕冷） | 丢弃 → no_new_facts=2 → **停滞** | 合并/去重 → 不触发停滞 → 正常收尾 |

医生 4 轮的有效怕冷信息全部保留（辨证时模型可见完整描述），流程不中断。

## 7. 边界与后续

- **规范化表覆盖有限**：目前仅 5 个枚举维度；未覆盖维度（如面色等自由文本）走 unknown 保守丢弃，
  行为不比旧版差。后续可升级为模型三分类（same/refine/conflict）而不改框架。
- **否定前缀保护**：防"不想喝水"误命中"想喝水"，但复杂否定句式（如"以前怕冷现在怕热"）仍可能
  判 unknown，属保守可接受。
- **停滞防护保留**：缺失维度 + 连续无进展时仍转人工（防呆不放松）。
