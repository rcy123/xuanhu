## 3. 修复详情

### 3.1 C1：维度 Rubric（`question_rubric.py`，新增）

**缺陷**：契约的 aspect 完全来自模型输出，模型可能漏问痰色/痰量等关键槽位（呼吸维度尤其如此）。

**修复**：

- `DimensionRubric`：`RubricAspect(criterion, required, conditional)`。
- `RESPIRATORY_RUBRIC_V1`：
  - required：「说明咳嗽是否有痰（干咳/有痰）」
  - conditional（触发键 `present_illness.sputum=有痰`）：「说明痰的颜色」「说明痰的量」「说明痰的质地（稀/黏/泡沫等）」
- `plan_contract_aspects(dimension, model_aspects, current_facts)` 契约生成算法：
  1. Rubric 必问项 + 已满足条件的条件项优先；
  2. 再并模型自身 criteria（去重）；
  3. 有痰事实出现后冻结痰相关条件项（一条粗糙事实永远无法关闭呼吸维度）；
  4. 契约总长 ≤ 4。

**设计约束**：未配置 Rubric 的维度（如睡眠）保持 legacy 模型原样行为，不扩拒绝面。

**接线**：`langgraph_intake.py::_compose_question` 在 `build_question_contract` 前调用
`plan_contract_aspects(selected_dimension, model_aspects, _active_fact_contexts(domain_state))`。

### 3.2 C2：语义充分性校验（`coverage_semantics.py`，新增）

**缺陷**：引文校验只证明"证据文本真实存在于回答"，不证明"证据文本回答了槽位"。模型可能把「有痰」引为痰色槽位的证据。

**修复**：`validate_aspect_semantics(aspect, evidence_text, current_status)`：

- `addressed` 而证据不含必需词 → 降级 `unclear`（留在残余追问，不静默满足契约）；
- `not_applicable` 而证据含矛盾词（如标"痰色 N/A"却引了"有痰"）→ 降级 `unclear`；
- 无词表命中 / 词命中 / 其他状态 → 返回 `None` 保留模型判定。

**降级策略三原则**（方案原文）：降级不误伤、不 reject、不扩拒绝面。

词表采用多词路由 `_SEMANTIC_HINTS: tuple[tuple[tuple[str, ...], _SemanticHint], ...]`，覆盖 composer 真实 criteria 变体（痰的颜色/痰液颜色/痰色/痰是什么颜色…），规避单一键子串不匹配问题。

**接线**：覆盖事件落账前执行 `_correct_coverage_semantics(candidate, contract, message_contents)`。

### 3.3 D1：契约账本被 observation 变化误清（`reducer.py`）

**缺陷**：`_apply_artifacts` 的 `invalidate_all_current` 由 `contract_changed or event_changed` 参与触发——任何一次提问（建契约）或覆盖事件落账都会把派生产品（方剂、证候、病历）整批置为 STALE，契约/事件账本被反复清空。

**修复**（`reducer.py:485`）：

```python
invalidate_all_current=observation_changed or safety_changed,
```

派生产品只应从临床事实（observations/safety）派生，从不从"提问/覆盖"派生；仅 observation 或 safety 变化才作废旧版本。

**验证**：`test_r9_domain_reducer.py` 中相关测试更名为 `*_does_not_invalidate_current_artifacts`，断言契约/事件变化不再 invalidate。

### 3.4 D2：损坏账本 fail-closed（`repository.py`）

**缺陷**：`_load_state` 组装 DomainState 时若账本损坏（如中间事件被删），可能构造出半成品状态继续参与折叠。

**修复**：DomainState 构造移入 try/except，账本一致性失败时抛 `RepositoryError.TRANSACTION_FAILED`（fail-closed），绝不静默降级。

**验证**：`test_r9_repository_integration.py::test_deleted_intermediate_event_fails_closed_with_envelope`（integration 标记）。

### 3.5 D3：掩码通配匹配 + 原始摘要（`span_matching.py`，新增）

**缺陷**：隐私管线在模型输入前把身份序列（手机号等）替换为等长 `█`（`project_model_input_identity_sequences`），模型引文含 `█` 而原始回答是数字 → 原先的精确匹配失败 → `COVERAGE_SPAN_INVALID`，或摘要错误地基于掩码文本。

**修复**：`app/schemas/span_matching.py` 新增共享匹配器：

- `span_quote_matches(content, start, end, quote)`：等长窗口内 `█` 通配任意单个原始字符（掩码等长故偏移对齐）；
- `find_quote_span(content, quote)`：定位引文的第一个匹配窗口。

**三处统一接入**（防止实现漂移）：

1. `intake_verifier._verify_coverage_binding` — 模型引文校验；
2. `question_contract.build_coverage_event` — 落库偏移修复 + `quote_sha256` 一律对**原始**回答子串取 sha256（掩码版摘要被排除）；
3. `intake_grounding._verified_message` — 回答文本接地校验。

**隐私语义**：持久化事件不存引文明文（quote-free），仅存 `quote_sha256`，验证时可对原始文本重算比对。

## 4. 真实后端验证（2026-08-12）

**环境**：`XUANHU_QUESTION_CONTRACT_ENABLED=true`、langgraph runtime、本地 PostgreSQL（容器 `xuanhu-postgres`）、真实模型网关（dmxapi）。

### 4.1 场景链（单会话端到端）

```
创建会话（主诉：我咳嗽一周了）
  → 十问扫查（二便/寒热/饮食/睡眠…，患者逐项作答，持续注入痰事实）
  → 呼吸维度契约出现：aspects = [说明咳嗽是否有痰（干咳/有痰）, 说明是否有痰,
      说明痰的颜色, 说明痰的量]  ← Rubric required + 有痰事实冻结条件项，共 4 项 ≤ 上限
  → 患者答「有痰」
      覆盖事件：是否有痰=addressed / 痰色=unanswered / 痰量=unanswered
      （模型未过度宣称，无需降级即正确；语义护栏保持待命）
  → 强制残余追问：「患者咳嗽有痰。那痰是什么颜色？多不多？」
  → 患者答「痰是黄色的，量不多」
      覆盖事件：痰色=addressed / 痰量=addressed → 链收敛
```

### 4.2 D3 手机号场景

患者回答「没有盗汗，也没有夜汗，我的电话是13812345678」绑定出汗契约：

- 事件证据 span `[0:27]` 覆盖整条原始回答，`quote_sha256` = sha256(原始子串)（含数字）✓；
- 摘要 ≠ sha256(掩码渲染) ✓（证明摘要基于原始文本而非模型视图）；
- 原始消息明文落库（隐私掩码只作用于模型输入，不作用于存储）✓；
- 全程无 `COVERAGE_*` 校验失败（掩码通配 verifier 通过）✓。
