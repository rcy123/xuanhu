## 3. 终审新增加固

### 3.1 L0：runtime 切换有权威台账

- `runtime.switched` 使用 allowlist-only 全局 `AuditEvent`，记录 deployment、operator、reason、from/to runtime 和时间。
- advisory transaction lock 串行化切换；migration `20260715_0012` 对 deployment 建 partial unique index。
- 配置默认 runtime 与持久台账不一致时，readiness 返回 503，默认会话在写入前失败。
- CLI 输出和异常固定脱敏。operator/reason 目前仍为部署侧声明，后续可由 CI/OIDC 身份和发布专用最小权限 DB role 增强不可抵赖性。

### 3.2 L1：进程级 LangGraph 生命周期

- FastAPI lifespan 每 worker 只创建一个 `AsyncConnectionPool`、`AsyncPostgresSaver` 和 compiled graph，并可靠关闭。
- 生产 message/advance 在 HTTP 幂等 claim 和业务写入前验证共享 runtime；启动失败不允许 request-local fallback。
- liveness 保持 200；runtime、checkpoint 表或版本不兼容时 readiness 为 degraded/503。
- Windows 使用 `xuanhu-api` Selector event-loop 启动入口，避免默认 Proactor 与 async PostgreSQL 组合不兼容。

### 3.3 L2：模型审计强制与重放完整性

- migration `20260715_0011` 增加 `policy_version`、input provenance 和数据库约束。
- input digest v2 绑定 canonical validated DTO 与实际有序 messages；不保存原始消息或 prompt。
- production recorder 为 required：`started` 写失败/超时则不调用 gateway，terminal 写失败则不返回 artifact。
- provenance 冲突、不同终态字段、相反终态和 terminal→started 重放固定拒绝；完全相同终态重放保持幂等。
- SHA-256 digest 用于完整性关联，不是保密机制；若未来扩大审计表读取/导出范围，应升级为带 key version 的 HMAC。

### 3.4 Outbox 运维闭环

- `/api/v1/metrics/outbox` 仅输出固定名称、低基数、无患者内容的 Prometheus 聚合指标。
- 5 条规则覆盖 backlog age、DLQ、health unavailable、publisher disabled 和按 job/instance 的 metrics missing。
- `promtool check rules` 与 `promtool test rules` 均进入 CI 和本地重新验收脚本。
- 仓库只交付可抓取端点和规则；机构 Prometheus/Alertmanager 安装、通知路由和真实告警演练仍由部署方完成。

## 6. 发布与安全边界

1. LangGraph recovery 当前只有安全隔离的 501，不是可用恢复能力。
2. migration 0011 的回填/约束和 0012 的唯一索引可能持有较强锁，大表上线需维护窗口或分阶段 backfill/validate/concurrent index 方案。
3. runtime switch CLI 的 `--reason` 可能进入进程参数和 shell history；只应填写非敏感工单号，后续可增加 stdin/`--reason-file`。
4. 结构化安全表单无具名 `X-Doctor-Id` 时只能称为 system-recorded input，不能写成“医师已确认”。
5. 本报告不声明外部 Prometheus/Alertmanager 已部署，不声明 L5～L9 已开始或完成。
