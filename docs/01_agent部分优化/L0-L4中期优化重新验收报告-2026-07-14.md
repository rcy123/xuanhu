## 4. 关键独立验收

- 真实双操作系统进程以同一公开幂等 key 并发创建，仅有一个 ConsultSession/claim，两个响应数据一致且一个为 replay。
- 真实 PostgreSQL 写入 Gate/Artifact 后关闭 writer、重置应用工厂，再经真实 FastAPI GET 重建权威 Read Model；伪造 snapshot 不生效。
- 单个 Outbox source event 经 Redis Stream 到达两个独立 SSE consumer，每个 consumer 恰好收到一次；Redis 只保留一次发布。
- Outbox ack 崩溃后 lease 接管不会重复写 Stream；最大重试进入 durable DLQ；health/readiness 可见积压、最老年龄和 dead letter 阈值。
- 三个临床临时缓存各写入 10,000 个 key 后仍不超过 256；模型失败、验证失败、取消和 terminal 路径均执行清理。
- 迁移 fixture、Redis client、asyncpg engine 与 pytest event loop 的生命周期已重做；两次独立全量运行均能重新创建并清理 worker 数据库/Redis DB。

## 5. 权限与产品边界

1. 创建页结构化安全表单是直接输入，不是模型推断。有 `X-Doctor-Id` 时记为 doctor；缺失时当前记为 system，只能描述为“系统记录的表单输入”，不得写成“已获具名医师确认”。
2. 模型抽取的过敏、妊娠、哺乳、当前用药等只进入 proposed ledger；必须经过医师 confirm/reject/retract 才进入权威 SafetyProfile。
3. LangGraph recovery 当前是安全隔离的 fail-closed 501，不是可用的恢复实现；实现专用 Recovery Adapter 属于后续阶段。
4. Outbox 告警当前通过 `/health/outbox`、`/health/ready` 的 degraded 信号和 warning 日志暴露；尚未绑定外部 Alertmanager、短信或 IM，部署方必须接入现有监控平台。
5. Redis Stream 近似保留 1,000 条；去重 hash/order 同样硬限制为 1,000，并有默认 86,400 秒滑动 TTL，避免长会话无界增长。
6. 仓库历史 `ruff format --check` 与 Alembic autogenerate 仍存在本次范围外的既有基线漂移；当前正式门禁是 Ruff lint、mypy、迁移唯一 head/往返和运行时 schema 验证。若未来把 formatter/autogenerate check 升为 CI 硬门禁，应先单独建立基线整改任务，不应在本次安全提交中机械重写历史文件或删除 LangGraph checkpointer 外部表。
