## 0. TL;DR

- 当前实现把 PII 脱敏放在 **ContextBuilder 投影边界**，用**黑名单匹配范式**在已组装、已转义、已跨层混合的自由文本上扫描号码，再叠加一份"临床豁免"白名单。
- 这导致**攻击面是无穷集**（所有 Unicode 规范化 / JSON 转义 / 全角 / 同形 / 跨分片重组的形态组合），133 批返工每批关闭一个 family、下一个 family 立刻出现，**不可收敛**。
- 真正能收敛的是**架构层改变**：把脱敏上移到**数据入口**（Intake 抽取）做确定性 pseudonym 化，并在 **Gateway 拼接边界**做一次 fail-closed 兜底扫描；临床豁免反转为**冻结白名单**。
- 本提案**超出 AR-B-031 现有范围**（只允许改 ContextBuilder 投影边界），需要项目经理批准**范围变更/重新基线**后方可实施。

## 2. 根因分析

### 根因 1：脱敏点放错位置

`_redact_user_text` / `_redact_free_text`（`context.py:3197`、`3213`）在 `ContextBuilder.build()` 的**投影时刻**扫描已组装好的自由文本。投影时刻是数据**最晚**的可干预点：此时原文已被 NFKC 规范化、已被 JSON 序列化、已被跨消息拼接、已被 clinical marker 包裹。脱敏必须在这个点上**逆向还原所有可能的混淆形态**才能识别 PII——而混淆形态有无穷多种。

**反例**：如果脱敏发生在 Intake 入口（数据**最早**的可干预点），此时输入是**一条原始患者消息**，没有 JSON 转义、没有跨层拼接、没有临床 marker 包裹。同一个手机号 `13...` 在入口处是裸串，在投影处可以是 `13...`、`１３...`（全角）、`1\\u0033...`（混合转义）、跨 3 条消息分片。**入口脱敏把无穷集降为一个有穷集**。

### 根因 2：黑名单匹配范式

`_match_identity_number` / `_match_direct_identity_number` / `_match_legacy_identity_number` / `_scan_digit_corridor`（`context.py:4518` 起）都在做"这串数字**像不像**身份证/手机号"。这是**漏报范式**：漏一个变体就泄露。

正确范式是**白名单拒绝**：`user` 层出现的任何连续数字 token，**除非属于明确冻结的临床生命体征 scope**，否则一律脱敏。但当前 `_identifier_span_is_proven_clinical_measurement`（`context.py:6469`）本身又是黑名单——用 `_CLINICAL_TRUST_CONFLICT_TOKENS`（`context.py:902`，含 `not/fake/test/simulation/non-vitals`）来排除"假临床"。两层黑名单叠加，于是攻击者只要用一个不在黑名单里的词（如 `pharmacistphone`、`cardiologistid`）就能骗过豁免。B130 之后反复出现的"普通业务号被误脱敏 vs. 假临床词骗过豁免"两难，就是范式错误的必然后果。

### 根因 3：单文件 1 万行，单点累积复杂度

`context.py` 同时承载：JSON span parser、semantic number tokenizer、digit corridor scanner、3 个 identity matcher、mobile matcher、label mask、subsequence DP、semantic view with spans、prompt layer boundary validator、structured validator、clinical measurement verifier、transport artifact mask、boundary piece witness……全部在一个模块、共享同一份 `_IdentifierScanSession` / `_SemanticClassificationCache`。

后果：
- **同一份文本被多个 scanner 各自规范一次**（`_normalized_semantic_view_with_spans`、`_normalized_semantic_text`、`_normalized_folded_prompt_view` 各跑一遍），产生二次复杂度。B133 Quality P1"numeric token 循环内整段 alpha 重扫导致平方级路径"就是。
- **修复一个 family 意外打破另一个 family 的临床豁免**。B133 full gates 首轮 `1 failed`（B74 安全临床 vitals 被全局 `_user_identifier_spans` 跨片比较误拒）就是。
- **跨分片重组靠多份独立扫描拼凑**（`_redact_prepared_contents` 在 `context.py:3242` 拼接后重扫 + `_unsafe_identifier_witnesses` 在 `8142` 找跨片 witness + `_new_identifier_label_scope_across_pieces` 在 `6566` 检查 label scope），三套机制各自有盲区，B133 的"跨 3~5 分片 escape/label 重组"就是它们任一都覆盖不全的组合盲区。

### 根因 4：跨分片重组不可靠单点扫描解决

`_redact_prepared_contents` 先逐条脱敏（`local_redactions`），再拼接重扫（`joined_spans`），再把跨片 span 映射回各消息（`context.py:3296-3342`）。但：
- 跨片 span 的"临床豁免"判定 `_identifier_span_is_proven_clinical_measurement` 是黑名单（见根因 2）。
- transport artifact mask、boundary piece witness、subsequence DP 是**三套独立机制**，没有统一的"在最终 Gateway 拼接边界做一次权威扫描"。
- Gateway 拼接发生在 `runtime.run()` 之前，但拼接后的最终消息串**没有再过一次 fail-closed 扫描**——这正是 B133 "跨 3~5 分片 Context/raw/typed/Gateway 重组"能泄露的架构原因。

## 3. 目标架构

### 3.1 三层脱敏，各司其职

```
患者消息
   │
   ▼
[层 1: 数据入口脱敏]  ← IntakeExtractionAgent 抽取前，在 build_intake_context 之前
   │  · 输入：单条原始患者消息（无 JSON 转义、无跨层拼接）
   │  · 动作：识别裸串手机号/身份证号 → HMAC 假名化（长度保持）
   │  · 临床豁免：冻结白名单（体温/血压/心率/呼吸/血糖等 + 精确数值范围）
   │  · Domain State 只存假名，原文不进入任何下游
   ▼
[层 2: ContextBuilder 投影]  ← 保留但大幅瘦身
   │  · context 层：仍走 allowed_fields 白名单投影 + scalar 边界检查
   │  · user 层：因为层 1 已假名化，此处只需轻量兜底（见根因消除）
   │  · 删除：semantic number tokenizer、digit corridor、3 个 identity matcher、
   │          clinical measurement verifier、transport artifact mask、boundary witness
   ▼
[层 3: Gateway 拼接边界兜底]  ← 新增
   │  · 在 runtime.run() 前，对最终 messages 串做一次 fail-closed 扫描
   │  · 只检查"层 1 应该假名化但漏掉的裸 PII"（一个极简裸串匹配器）
   │  · 命中即 ContextBuildFailed，绝不把含裸 PII 的消息发给模型
   ▼
模型 Gateway
```

### 3.2 关键设计决策

**D1. 临床豁免反转为冻结白名单。**
当前 `_CLINICAL_TRUST_CONFLICT_TOKENS` 黑名单（`not/fake/test/simulation/...`）删除。改为一份**不可变的"临床生命体征字段表"**：
- 字段名白名单（`temperature`、`blood_pressure_systolic`、`heart_rate`、`respiratory_rate`、`blood_glucose`、`spo2`、`weight`、`height`、`bmi`、…，含 CJK 别名）。
- 每个字段绑定**单位 + 数值范围**（如体温 34–43°C、心率 20–250 bpm）。
- 只有"字段名命中白名单 AND 数值在范围 AND 单位匹配"三者交集，才保留数字。
- 其余 `user` 层连续数字 token **一律脱敏**，包括日期形状合法的 15 位业务号（记录为 P2 可用性影响，但**不**放宽 fail-closed）。

**收益**：彻底消除"假临床词骗过豁免"（B133 `not/fake/simulated` P1）和"普通业务号误脱敏 vs 假临床词骗过"两难。白名单是冻结的，攻击者无法用一个不在表里的词骗过。

**D2. Pseudonym 化在入口完成，Domain State 只存假名。**
现有 `_projected_pseudonym` / `PseudonymKeyProvider`（`context.py:3180`、`85`）基础设施保留，但调用点上移：在 Intake 抽取前，对每条患者消息做一次 pseudonym 化，假名写入 `UserMessageProjection.content`（已是 byte-for-byte 稳定的类型，`context.py:91`）。下游 ContextBuilder 看到的 `user_messages` 已经不含原始号码。

**收益**：投影边界不再需要识别无穷的 Unicode 变体——因为投影时根本**没有原始号码可泄露**。攻击面从"所有 Unicode 形态"降为"入口处的一段确定文本"。

**D3. Gateway 拼接边界加一次 fail-closed 兜底。**
新增一个极简裸串匹配器（只识别入口层 1 应该处理但漏掉的**裸** 11 位手机号 / 18 位身份证，不处理转义/全角/跨分片——那些在层 1 已不存在）。在 `runtime.run()` 前对最终 messages 串扫描，命中即 `ContextBuildFailed`。

**收益**：兜底跨分片重组（B133 "跨 3~5 分片 Gateway 重组" P1）——即使层 1 因 bug 漏掉，层 3 兜住。层 3 的匹配器极简，无二次复杂度。

**D4. 拆分 context.py。**
按职责拆分为独立模块（每个 scanner 只跑一次规范化）：
- `app/agent_runtime/context/__init__.py`（公共 API：`ContextBuilder`、`ContextPacket`、异常类）
- `app/agent_runtime/context/_json_parser.py`（`_JsonSpanParser` 及相关）
- `app/agent_runtime/context/_pseudonym.py`（`_projected_pseudonym`、`PseudonymKeyProvider`）
- `app/agent_runtime/context/_redaction_entry.py`（层 1 入口脱敏，新）
- `app/agent_runtime/context/_gateway_guard.py`（层 3 兜底，新）
- `app/agent_runtime/context/_clinical_whitelist.py`（D1 冻结白名单，新）
- `app/agent_runtime/context/_projection.py`（层 2 瘦身后的投影）

**收益**：消除"同一份文本多 scanner 各规范一次"的二次复杂度（B133 Quality P1 平方级路径）。每个模块单一职责，复审可逐模块验证。

**D5. 范围明确排除项（不变）。**
本方案**不**触碰：`triage_precheck.py`、临床红旗规则、原始 Domain 事实语义、L5～L9、UI/持久化、默认开关、临床决策阈值、模型输出事实。这些与 AR-B-031 现有排除项一致。

## 4. 迁移步骤（分批，每批可独立验收）

> 每批严格遵循"先红后绿"：先在未改源码上建立失败回归（绑定生产/测试 SHA-256），再修复，再绿。每批结束后三路独立复审 P0/P1=0 才进下一批。

### 批次 A：建立临床生命体征冻结白名单（D1）
- 新建 `_clinical_whitelist.py`，定义不可变字段表（字段名 + 单位 + 数值范围，含 CJK 别名）。
- 红测：B133 `not/fake/test/simulation/non-vitals` 误判 clinical 的样例 → 期望"不豁免，脱敏"。
- 绿测：B74 真实临床 vitals（体温/血压/心率）→ 期望"保留"。
- 风险：可能误拒某些合法但未登记的生命体征 → 登记为 P2，不放宽白名单。

### 批次 B：实现入口 pseudonym 化（D2）
- 新建 `_redaction_entry.py`，在 `build_intake_context`（`intake_extraction.py:95`）调用 `ContextBuilder.build` 之前，对 `current_messages` 逐条 pseudonym 化。
- 红测：B130～B133 所有"raw/typed USER、Context fields、Gateway 前消息可见 `13e9`"样例 → 期望"入口已假名化，投影见假名"。
- 绿测：现有 Intake E2E（L3-5 真实 PG）保持通过，原始 Intake DTO 与注入文本层级不变。
- 风险：pseudonym key 必须运行时注入（已有 `PseudonymKeyUnavailable` fail-closed），缺失即拒绝。

### 批次 C：瘦身 ContextBuilder 投影（D4 部分）
- 删除 semantic number tokenizer、digit corridor、3 个 identity matcher、mobile matcher、clinical measurement verifier、transport artifact mask、boundary witness。
- 保留：allowed_fields 白名单投影、scalar 边界检查（瘦身后）、JSON span parser（供 structured user 用）。
- 红测：层 1 + 层 3 已覆盖的样例在此层应"无 PII 可泄露，直接放行"。
- 绿测：现有 L2-3 context builder 专项（`test_l2_3_context_builder.py` 180 test）保持通过。
- 风险：删除可能误伤依赖这些 scanner 的既有正向断言 → 逐项迁移到层 1/层 3。

### 批次 D：Gateway 拼接边界兜底（D3）
- 新建 `_gateway_guard.py`，在 `runtime.run()` 前对最终 messages 串做极简裸串扫描。
- 红测：B133 "跨 3~5 分片 Context/raw/typed/Gateway 重组"样例 → 期望"层 3 兜住，ContextBuildFailed"。
- 绿测：正常会话（无 PII 或已假名化）→ 期望"放行"。
- 风险：极简匹配器可能漏报新形态 → 但因层 1 已无原始号码，层 3 只需兜"裸串"，攻击面已大幅收窄。

### 批次 E：拆分 context.py（D4 完成）
- 按模块边界拆分，公共 API 不变（`ContextBuilder`、`ContextPacket`、异常类签名不变）。
- 绿测：全量后端、Ruff、mypy、lock、diff check 通过。
- 风险：import 路径变更可能破坏外部引用 → 保留 `context.py` 作为 re-export shim 或更新引用。

### 批次 F：三路正式复审 + full gates + 验收 + 提交
- 冻结统一 manifest，三路独立复审 P0/P1=0。
- full gates（性能阈值不放宽，低配硬件噪声用隔离复跑）。
- 验收、精确暂存、提交、clean exact-HEAD 复验。

4. **是否批准 context.py 拆分**（批次 E）：影响面较大但消除二次复杂度。

## 8. 不批准时的退化路径

若项目经理**不批准范围变更**，则只能在 AR-B-031 现有范围内继续逐批收口。基于 133 批的模式，**收敛性不保证**——预期会继续出现新的 Unicode/转义/跨分片 family。此路径下建议：
- 把"架构性重写"作为 P1 登记到后续优化台账，等待下一次范围窗口。
- 当前范围内只做"维持 P0/P1 不恶化"的最小修复，不再追求彻底关闭 AR-B-031。
- L5 保持 NO-GO，G0 保持打开。

## 9. 后续优化台账（非阻塞，本方案范围外）

- 跨分片保守 DP 误报（B133 P2）

## 10. 结论

当前 L4.5-11 的不可收敛性是**架构问题，不是实现问题**。在投影边界做黑名单正则对抗，攻击面是无穷集，133 批返工已证明此路不通。本方案通过"脱敏上移到数据入口 + Gateway 兜底 + 临床白名单反转 + 模块拆分"四个架构改变，把攻击面从无穷集降为有穷集，使 AR-B-031 可收敛关闭成为可能。
