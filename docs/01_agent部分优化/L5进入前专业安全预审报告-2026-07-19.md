> 日期：2026-07-19（Asia/Shanghai）
> 性质：AI 辅助的工程/医疗安全/法规资料预审
> 当前决议：**L5 NO-GO（不准入）**
> 适用边界：本报告不是临床审定、医师签字、医疗器械分类结论、法律意见、伦理批准或上线许可。

## 1. 执行摘要

本次已完成进入 L5 前的资料收集、现状对照与 AI 工程预审。结论是：当前可以继续完成
L4.5-11 的工程闭环、整理 L5 任务包和准备审查证据，但不得开启 L5 业务实现、真实患者服务、
自动处方、正式病历生成或对外发布。

不准入的直接原因是：

1. L4.5-11 / AR-B-031 尚未完成同哈希代码复审、正式验收、提交和 clean exact-HEAD 复验；
2. L4.5-02 红旗规则仍缺具名合格临床专业人员对精确版本的签署；
3. 产品预期用途、排除用途、残余风险与受控环境尚未由产品和医疗安全负责人批准；
4. 互联网诊疗、医疗器械/软件属性、生成合成内容标识、个人信息和伦理适用性尚未由有权专业人员决定；
5. 现有“医师确认”路径不具备可作为 L5 强制人工复核边界的身份、资质、精确状态绑定和签署证据。

## 2. 范围与方法

预审对象包括：

- `triage-raw-text-precheck.v1` 与现有 L4.5-02 人工审定签署单；
- L5 计划中的 Safety Gate、Safety Explanation、医师 HITL interrupt/resume 和修改后二次审查；
- 当前 review API、doctor review 持久化、state version 和 safety rule run 绑定；
- 中国现行的互联网诊疗、个人信息、网络数据、生成合成内容标识、医疗器械与科技伦理资料；
- WHO、IMDRF 和 NIST 的医疗 AI/大模型风险治理资料。

方法是“规范要求→当前实现证据→缺口→准入条件→责任人”的可追溯对照。本次没有执行
渗透、漏洞利用、端口/网络扫描或其他网络安全操作，也没有申请或使用受信访问。

## 6. 通过准入后的 L5 任务发布条件

### L5-1 确定性 SafetyRuleEngine adapter

- 仅消费规范化权威状态和不可变规则版本；
- 结果幂等、可重现、事务原子、有界，缺字段/解析错误/版本不一致必须 fail closed；
- 结果绑定 patient/session/state/formula/rule 版本与 canonical digest。

### L5-2 限权 SafetyExplanationAgent

- 只能解释确定性结果，不得改写 issue、severity、gate decision 或处置；
- 每个声明与规则/证据一对一引用，无支持内容必须省略而不是推测；
- 输入最小化，不携带无关患者身份或原文。

### L5-3 可验证医师 HITL interrupt/resume

- 服务端验证身份、机构、执业资质、角色与操作范围；
- challenge 绑定 tenant/session/thread/checkpoint/state/formula/patient/safety-run/rule/model/prompt/KB/tool
  版本、nonce、发出时间和失效时间；
- 医师页面显示的精确内容与服务端签署 digest 一致；
- 重放、过期、跨租户、跨会话、旧版本一律拒绝；interrupt 前不发生不可逆业务效果。

### L5-4 修改后全量重检与旧批准失效

- 处方修改创建新版本，必须全量重跑确定性规则并生成新 challenge；
- 任何内容/状态变化使旧批准自动失效，红旗不得被修改动作清除或降级；
- 并发 resume 幂等，只有一次成功迁移；
- 没有当前有效 review 时，record/export/done 等后续路径不可达。

## 7. 专业签署责任边界

| 结论/签署 | 不可替代的责任人 |
|---|---|
| 红旗规则临床适宜性、阈值、处置与评估集 | 具名合格临床专业人员 |
| 单个患者的诊疗与处方决定 | 实际负责诊疗的合格医师 |
| 预期用途、禁忌/排除用途、残余风险与受控部署 | 产品负责人 + 医疗安全负责人 |
| 医疗器械/软件、互联网诊疗、AIGC 标识与其他法定适用性 | 有权法务/注册专业人员 |
| 个人信息、数据分类分级、去标识化与保留/删除 | 隐私/数据负责人 |
| 伦理审查是否适用及审批 | 有权伦理组织 |
| 最终发布与停用 | 机构、产品、医疗安全与发布责任人 |

AI 可以辅助整理资料、设计测试、检查证据一致性和起草报告，但无权填写上述人类责任人的姓名、资质、
意见或签章，也无权将空白签署视为默认同意。
