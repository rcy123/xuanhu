## 2. 状态更新事务

一次状态变化必须按下面的最小事务更新，禁止只改其中一处：

### 发布任务

1. 在任务台账把任务改为“已发布 / 待验收”；
2. 创建任务书，写明允许范围、禁止范围、验收命令和停止条件；
3. 更新当前状态的“唯一下一动作”；
4. 若发布依赖新决策，同时追加决策记录。

### 开发交付

1. 创建或更新对应 handoff；
2. 任务台账改为“已交付”；
3. handoff 必须列出实际 diff、测试结果和未决风险；
4. 不得由开发交付声明替代 PM 验收。

### 验收通过

1. PM 独立核对代码、测试和范围；
2. 在 handoff 增加 PM 验收段落；
3. 追加验收记录；
4. 更新任务台账、阻塞表和当前状态；
5. 提交后确认 clean worktree；需要 exact-HEAD 时再执行对应门禁；
6. 每次只发布一个下一任务。

### 验收失败

1. 登记或更新 `AR-B-xxx`；
2. 任务改为“返工中 / 验收未通过”；
3. 只发布限定返工，不顺手扩展阶段或业务语义；
4. 在验收记录中保存失败证据和停止位置。

## 3. 编号规则

- 产品工程任务：`L{阶段}-{任务}`，子任务继续追加序号，例如 `L4.5-11-0`。
- 工程阻塞：`AR-B-001` 递增。
- 项目决策：`DEC-YYYYMMDD-NNN`。
- 验收记录：`ACC-YYYYMMDD-NNN`。
- 外部门禁：`EXT-001` 递增，不与工程阻塞混用。

## 4. 权责边界

Codex 可以承担工程项目经理、任务发布、范围审查、自动化验收和证据维护，但：

- 不代签临床、隐私、法务、伦理或机构审批；
- 自身复核不计作“独立 reviewer”意见；
- 工程测试通过不等于临床可用或生产获批；
- 不因文档声明覆盖当前代码和 Git 事实。

## 5. 归档策略

- 历史文档保持只读，不回写当时的百分比、失败批次或旧测试数字。
- 已失效方案必须在文件头标记“历史参考/已暂停”，并在文档索引中登记替代文档。
- 当前台账不复制完整历史，只保留活跃状态和指向归档的链接。
- 所有正式管理、任务、交付和验收文件必须进入 Git，不得只留在 ignored worktree。
