## DEC-20260721-008 L4.5-11 不采用宽泛数字匹配加临床白名单补洞

- 决策：当前有限保护集合以明确手机号、身份证号及经批准的有限分隔 grammar 为主；体温、血压、心率、血糖、日期和剂量作为必须保持的负向不变量。

- 边界：自由文本姓名、其他证件和新增格式必须作为残余风险或另行发布的有限任务，不得用“所有 PII”概括。
- 外部门禁：若未来确需新增临床数值白名单或范围规则，必须具名临床 owner 审核；Codex 工程验收不代签。

## DEC-20260722-009 L4.5-11 采用入口等长投影与 Intake-only Runtime 门禁

- 决策：入口层以有限 token/原始坐标流遮罩 Intake source messages；最终兜底放在 `AgentRuntime._call_gateway()` 调用 Gateway 方法之前，并按 `INTAKE_AGENT_NAME` 精确启用。
- 代码原因：Runtime 对真实 Gateway 传 `max_requests=1`，所以目标 Intake 路径只允许一次 HTTP 尝试，且在解析失败时不会进入独立 JSON fallback；在共享 Gateway 内引入 Runtime 失败码会破坏依赖方向，也难以证明只影响 Intake。
- 消息边界：相邻 message 之间保留虚拟零宽 `B`，scanner token 携带 `(message_index, raw_char_index)`；入口命中映射回每条原文等长遮罩，Runtime 命中只拒绝。
- 任务拆分：L4.5-11-1 独占 scanner/projector、入口集成和临床负向测试；L4.5-11-2 独占 Runtime/specs、零调用与审计测试；删除独立的 L4.5-11-3。
- 非目标：Legacy、其他 Runtime Agent、直接 Gateway 调用、自由文本姓名、其他证件和完整隐私合规声明。
- 验收目标：`22feb390425c3b4fc4349980566a5c80314e60d0`；该提交只含方案和 handoff，不关闭 AR-B-031。
