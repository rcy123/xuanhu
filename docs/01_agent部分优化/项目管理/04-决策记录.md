## DEC-20260722-018 L5-3 到期、恢复与当前 authority 必须在同一状态不变量内闭合

## DEC-20260722-020 live mutation 与 restore 必须共享可达历史因果谓词

- 事实：R2 的 restore 已验证单 attempt 的 `issued <= staged <= applied < expiry`，但 live stage/apply 只查 exclusive upper bound；因此 clock 回拨时 live 可生成随后被自身 snapshot validator 拒绝的历史。
- 决策：stage/apply 在 mutation 前分别验证 `now >= issued_at` 与 `now >= staged_at`；失败不得有部分 mutation。成功 live snapshot 与 restart restore 必须由同一组因果 helper/谓词判定有效。
- 序列：一个 challenge applied 后 live store 不再允许 stage 其他 sealed attempt；restore 必须用 append-only transition sequence 证明所有 stage 均早于第一个 applied transition，并验证 winner 三条 applied transition 的固定连续顺序。
- 校准：fake clock 不要求跨 attempts 全局单调；cross-attempt 关闭状态用 sequence 表达，时间 lower bound 只在所属 challenge/attempt 内表达。
- 范围：R3 只关闭 live/restore 因果漂移，不实现 L5-4 formula revision、stale 标记、full safety recheck 或任何 Runtime/外部集成。

## DEC-20260722-021 双 append-only 日志必须证明同一应用顺序

- 事实：R3 分别验证 event/transition 的连续 sequence、derived refs、逐记录绑定与 cardinality，但未比较两个日志的应用相对顺序；反转 events 并重算 refs 后形成 schema-valid、live-unreachable history。
- 决策：按各自连续 sequence，`events` 的 `resume_attempt_ref` 元组必须精确等于所有 `review_applied` transitions 的 `resume_attempt_ref` 元组；任一顺序漂移 fixed chainless reject。
- 原因：live `apply()` 在单 store lock 内先原子追加 winner 三条 transitions，再追加对应 event；后续 apply 不可能只在一侧插队。逐记录 ref 完整性不能替代跨日志顺序完整性。
- 校准：顺序 authority 来自 append sequence，不比较跨 challenges/events 的时间戳；injected fake clock 的跨 attempt 回拨正例必须保持。
- 范围：R4 只关闭这一 P2，不扩展到 L5-4、Runtime、DB、HTTP、真实身份/签署或外部持久化。

## DEC-20260724-045 L6-2 独立复审发现 P2=2 — 撤回 accepted 并发布 L6-2-R1

- 决策：经独立 adversarial 复审，L6-2 第 1 次交付（`d8dfa44`）的 `SandboxRecordConsistencyVerifier` 在测试覆盖盲区上存在两个 P2 缺陷，必须撤回 `ACC-20260723-050` accepted 结论，发布 bounded R1。
- 复审：PM 在 10 项 adversarial 探针中发现 2 项 FAIL，覆盖 L6-2 交付测试未触及的输入类型矩阵边界。

### 根因分析

**P2-1: verifier 对 bytes/str 快照双重序列化，fail-closed 拒绝合法输入**

- 位置：[sandbox_record.py:107-108](app/agent_runtime/sandbox_record.py#L107-L108)（verifier）、[sandbox_record.py:252-253](app/agent_runtime/sandbox_record.py#L252-L253)（assembler）
- 代码模式：
  ```python
  if isinstance(recheck_snapshot, SandboxRecheckSnapshotV1):
      snapshot = recheck_snapshot
  else:
      snapshot = SandboxRecheckSnapshotV1.model_validate_json(
          canonical_review_bytes(recheck_snapshot), strict=True
      )
  ```
- 缺陷机制：`canonical_review_bytes(value)` 对任意对象调用 `json.dumps(_json_ready(value), ...).encode("utf-8")`。当 `value` 已是 `bytes`（例如 `canonical_review_bytes(snapshot)` 的输出）时，`json.dumps` 把 bytes 当作普通字符串序列化，产生 `"7b2261223a317d"` 这种 JSON 字符串字面量（不是原始对象）。`model_validate_json` 收到的是字符串字面量而非对象，报 `Input should be an object [type=model_type]` → 被 `except Exception: return False` 吞掉。
- 关键洞察：`canonical_review_bytes` **不是幂等的**。`canonical_review_bytes(canonical_review_bytes(x))` ≠ `canonical_review_bytes(x)`。对已序列化的 bytes/str 输入再调用 `canonical_review_bytes`，产生的是 JSON 引号字符串而非原始对象。
- 方向：fail-closed（拒绝合法输入而非放行非法输入），是功能缺陷而非安全漏洞，但违反 verifier 类型签名 `recheck_snapshot: object` 暗示的多态输入契约。
- 测试盲区：L6-2 的 16 个测试中，所有 `verifier.verify(record, recheck_snapshot=snapshot)` 调用都传 `SandboxRecheckSnapshotV1` 实例。没有测试传入 bytes、str 或 dict 类型的快照。

**P2-2: assembler 和 verifier 共享同一段双序列化代码，缺陷在两个模块中传播**

- 两处代码（assembler 的 `_build_record` 第 249-253 行、verifier 的 `_verify` 第 104-108 行）使用了完全相同的 `isinstance`/`canonical_review_bytes`/`model_validate_json` 模式。
- assembler 的 L6-1 测试只打了两条路径：`SandboxRecheckSnapshotV1` 实例（第 360-381 行）和 `dict`（第 388-399 行、第 449-480 行）。bytes/str 路径从未被测试。
- 在 assembler 中，bytes/str 双序列化失败表现为 `SandboxRecordError`（fail-closed），与 verifier 的 `False` 等价。
- 修复必须同时覆盖两个模块，不能只修 verifier 而不管 assembler。

### 缓解与修复要求

- 修复选项 A（推荐）：在 else 分支中增加对 bytes/str/dict 的显式分支：
  - `bytes` → `model_validate_json(recheck_snapshot, strict=True)`（Pydantic 接受 bytes）
  - `str` → `model_validate_json(recheck_snapshot, strict=True)`（Pydantic 接受 str）
  - `dict` → `model_validate(recheck_snapshot, strict=True)`
  - 其他 → `return False`（fail-closed）
- 修复选项 B：去掉 else 分支，只接受 `SandboxRecheckSnapshotV1` 实例，缩小类型签名。但这与任务书"允许从 sandbox_review.py、sandbox_recheck.py 读取已 accepted 的类型和常量"的契约精神不一致（bytes/str 是序列化输出的自然形式）。
- 测试要求：补输入类型矩阵测试（instance / dict / bytes / str / garbage），每个覆盖 verifier 和 assembler。

### 证据

- 10 项 adversarial 探针：A1-A5 PASS、A6 PASS（经分析 fixture 只有一个 item 导致 reversed 无效果）、A7-A8 PASS、A9 FAIL（bytes 快照被拒绝）、A10 PASS
- 手工复现：`canonical_review_bytes(canonical_review_bytes({'a':1}))` 返回 `b'"7b2261223a317d"'`（JSON 引号字符串），不是 `b'{"a":1}'`（原始 JSON 对象）
