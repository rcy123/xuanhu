## 1. 权威范围与结论

本包是当前个人学习工程沙盒的用途、数据边界、L5 工程设计和测试计划权威。根目录 `README.md`、既有产品文档、ADR-005 和《Agent 整体大修实施计划》中的医疗产品、Doctor Review、临床部署或生产目标，只保留为历史/未来目标背景，不授权当前使用。

《L5 进入前专业安全预审报告》中的 G1～G6、专业责任人和 NO-GO 结论继续完整适用于真实数据、患者服务、医师/医疗机构工作流、诊疗用途、公开服务、商业化、临床评价和人体研究。本包不关闭、不替代、不弱化这些门禁。

当前可达到的最强结论只有：

- L0～L4.5 已有工程证据可标记 `engineering_passed`；
- L5-PREP-0 通过全部工程门禁后，个人学习、非临床、仅合成数据范围可标记 `sandbox_scope_satisfied`；
- G1～G6、EXT-001、EXT-002 对当前沙盒标记 `deferred_for_clinical_use` 或 `not_applicable_to_current_scope`，在触发真实/公开用途时恢复为 `external_approval_required`；
- 真实临床、患者服务、机构接入、商业化和公开生产使用继续 NO-GO。

本状态变化来自项目所有者对用途范围的调整，不是临床、法律、隐私、伦理或监管批准。

## 2. 项目用途与限制声明

### 2.1 Intended use

项目仅用于：

- 项目所有者个人学习；
- 软件架构、LangGraph 编排和状态机实验；
- 确定性规则适配、fail-closed、幂等、重放防护和并发控制练习；
- 使用固定虚构、程序生成或无个人属性技术数据的自动化测试；
- 安全机制、审计、回退和工程项目管理演练。

### 2.2 Excluded use

项目不得用于：

- 诊断、治疗、分诊、用药、处方或任何真实医疗决策；
- 为患者、医师或医疗机构提供服务或嵌入其工作流；
- 采集、导入、处理或保存真实患者、真实病历或可关联个人的数据；
- 临床研究、临床评价、医疗机构试点、互联网诊疗或人体研究；
- 对公网、第三方或商业客户提供医疗相关服务；
- 连接真实身份认证、真实病历、真实知识库、生产模型日志或外部临床系统；
- 声称临床有效、医疗安全、法律合规、隐私合规、医疗器械获批或获得专业背书。

当前代码、规则、样例、测试结果、解释和 Sandbox Reviewer 记录不能用于任何个体医疗决定。

### 2.3 运行边界

- `AGENT_RUNTIME_VERSION` 保持默认 `legacy`；
- `XUANHU_LANGGRAPH_PUBLIC_ENABLED` 保持默认 `false`；
- `VITE_LANGGRAPH_UI_ENABLED` 保持未设置或 `false`；
- 现有应用 runtime 没有全局 `sandbox-only` hard-off，Legacy consult/review/record 路由仍会注册，因此应用服务器、HTTP/E2E、容器和部署均**未纳入沙盒准入**；
- 本任务不启动应用、不连接数据库/Redis/Milvus/模型网关，不部署、不公开监听服务；
- 未来 L5 Sandbox 任务只可先以隔离单元测试和 fake adapter 证明工程不变量；任何公开、临床或生产开关不在授权范围。

## 5. 合成数据政策

### 5.1 允许的数据

仅允许以下三类，且必须有 manifest：

1. 人工编写的固定虚构 fixture，人物、标识、事件和文本均为构造内容；
2. 由仓库内可审计 generator 以固定 seed 生成的数据；
3. 不包含人物、健康、联系或行为属性的技术测试数据，例如版本、nonce、digest、错误码和状态机事件。

“已脱敏”“去标识化”“公开数据”或“模拟病历”本身不满足准入；如果原始来源可能是真实个人、外部语料、生产日志或聊天记录，则不得进入当前沙盒。

### 5.2 禁止的数据

- 复制、改写或翻译的真实病历、处方、就诊记录、聊天记录或客服记录；
- 真实姓名、手机号、身份证件号、地址、电子邮箱、机构就诊号或可组合重识别字段；
- 生产数据库导出、生产模型输入/输出/日志、监控 payload、错误 dump 或 checkpoint；
- 未经逐包说明来源的外部数据集；
- 仅以“去标识化”声称安全、但没有生成/来源证据的数据；
- 真实人物材料经替换少数字段得到的伪合成数据。

### 5.3 每个测试数据包的 manifest

manifest 至少包含：

| 字段 | 要求 |
|---|---|
| `schema_version` / `dataset_name` / `dataset_version` | 非空、版本化、不可复用旧版本覆盖内容 |
| `admission_scope` | 固定为 `personal_learning_synthetic_only` |
| `provenance_type` | 仅 `constructed_fixture`、`generated_with_fixed_seed` 或 `non_personal_technical` |
| `source_statement` | 明确“不来自真实病历、个人记录、生产日志、聊天记录或外部数据集” |
| `generator_path` / `generator_version` / `generator_digest` / `seed` | 程序生成时全部必填；固定 fixture 显式填 `not_applicable` 并说明作者构造 |
| `case_count` / `content_sha256` | 与 canonical serialization 的实际内容一致 |
| `created_at` / `created_by_test_role` | 只使用测试角色命名，不写临床资质 |
| `prohibited_identifier_scan` | 记录扫描工具/版本、规则集、时间和结果；不记录命中的原始敏感值 |
| `label_status` | 固定包含 `not_clinically_adjudicated` |

版本或内容改变必须生成新 digest；旧 manifest 不得继续授权新内容。

### 5.4 疑似真实数据处置

1. **停止**：停止测试、导入、索引、模型调用和提交；保持公共开关关闭。
2. **限制/隔离**：只记录路径、hash、大小、tracked/ignored 状态和检测类别；不把原文复制到 issue、handoff、日志或聊天。由项目 owner 或具名数据/隐私责任角色决定隔离位置和访问人。
3. **分级**：区分已确认真实/可关联数据、疑似数据、仅来源不明数据；在结论前一律不得准入。
4. **升级**：重新打开 G4/EXT-002；涉及真实医疗/研究时同时重新打开其他适用门禁。
5. **授权删除**：只有明确有权的数据 owner 在确认保留义务、Git 历史、备份、缓存和派生物范围后才能批准删除。Codex/Agent 不擅自删除。
6. **验证**：授权处置后重新扫描工作区、历史、缓存和派生物；保留不含原值的事件证据与关闭结论。

## 7. L5 沙盒工程安全架构

### 7.1 共同信任边界

```text
Synthetic Fixture + Manifest
        ↓ strict schema/version/digest
Authoritative Sandbox Snapshot
        ↓ canonical input envelope
L5-1 Deterministic Safety Adapter ──→ immutable rule result
        │                                  │
        │                         decision/issues/digest authority
        │                                  ↓
        └──────────────────────→ L5-2 Explanation (optional, non-authoritative)
                                           ↓
                         L5-3 Sandbox Reviewer interrupt/challenge
                                           ↓ exact one-time resume
                         L5-4 modify → invalidate → full recheck
                                           ↓
                                  sandbox_simulation_complete
```

所有边只处理 synthetic/test 命名的身份和数据。不存在真实患者、医师、机构、处方签发或外部临床系统边界。

### 7.2 共同版本与 digest 绑定

canonical envelope 必须绑定：

- `sandbox_schema_version`、`graph_version`、`adapter_version`；
- `test_session_id`、`test_state_version`、`test_formula_revision`；
- `synthetic_dataset_name`、`synthetic_dataset_version`、`synthetic_dataset_digest`；
- `rule_version`、`rule_bundle_digest`；
- 规范化输入 canonical JSON 的 `input_digest`；
- 输出 canonical JSON 的 `result_digest`。

canonical JSON 必须固定 UTF-8、字段顺序、数字/单位格式、空值规则和数组排序。缺字段、未知字段、无法规范化、版本不一致或 digest 不一致全部 fail closed。

必须区分两个摘要：

- `decision_subject_digest` 只绑定 canonical 业务输入、精确 artifact、规则包和 adapter 版本，不含时间、trace、run ID 或 nonce，用于证明同输入同裁决；
- `run_envelope_digest` 在 subject 上再绑定 command/run/trace，用于幂等和审计，不得影响裁决。

### 7.3 L5-1：确定性 SafetyRuleEngine adapter

状态机：

```text
received
  → validate_envelope
      ├─ invalid → rejected_fail_closed
      └─ valid → resolve_exact_rule_bundle
                    ├─ missing/mismatch → rejected_fail_closed
                    └─ run_deterministic_rules
                          → verify_result_shape_and_digest
                              ├─ invalid → rejected_fail_closed
                              └─ valid → persist_append_only_result → decided
```

不变量：

- adapter 只消费 frozen `SandboxSafetySubjectV1`，包含 exact formula/profile artifact ID、revision、content digest、Domain state version、graph/adapter/rule bundle 版本和 digest；不接受调用方自报“已验证”对象；
- 相同 canonical input + rule bundle 必须产生逐字节相同的 decision/issues/result digest；
- 规则包必须冻结静态规则、药材/别名、单位/剂量等全部 evaluator 输入并给出 canonical SHA-256；不得仅记录 `v1.0.0` 后读取可变当前表；
- 输出必须是 frozen `SandboxSafetyResultV1`；规则执行顺序和 issue 排序固定；issue ID、severity、gate decision 只由确定性层产生；
- 缺字段、未知版本、解析/标准化/规则加载/持久化错误一律拒绝，不返回部分通过；
- engine 执行与 append-only result 在受控事务中形成一个可恢复结论：锁定 test session、比较 expected state version、重读 exact artifact/digest、写 safety artifact + gate + outbox/幂等结果；
- 不调用 LLM、不调用外部网络、不执行 review、record、export 或阶段完成；
- 现有 `SafetyRuleEngine.check()` 会加载可变数据库并写 `safety_rule_runs`，其 `persist_result()` 还可保存调用方构造结果；L5 adapter 不得暴露该注入入口，也不能在未建立固定规则包、exact snapshot/digest 和事务适配前视为已完成。

### 7.4 L5-2：SafetyExplanationAgent 限权解释

状态机：

```text
rule_result_decided
  → build_allowlisted_explanation_input
  → generate_optional_explanation
  → verify_references_and_non_interference
      ├─ invalid/error → explanation_unavailable
      └─ valid → explanation_attached
```

不变量：

- 解释只读取不可变 `result_digest`、decision、issue IDs、severity 和 allowlisted 规则说明；
- 输出不能包含或写回 decision、severity、issue 集合、处置、formula 或 review action；
- 每个解释句必须引用现有 issue/rule ID；无支持内容省略，不猜测；
- 解释数量不得超出输入 issue 数；解释失败、超时、解析失败只导致 `explanation_unavailable`，不得改变确定性结论；
- 输入不携带姓名、联系方式、真实身份、原始病历或无关自由文本；
- 解释必须显示 `sandbox_test_only_not_medical_advice`。

### 7.5 L5-3：Sandbox Reviewer interrupt/resume

不得使用“已认证医师”“医师签署”或类似表述。所有身份/资质/签署字段必须采用测试命名：

- `sandbox_test_reviewer_id`，例如 `sandbox-reviewer-fixture-001`；
- `sandbox_test_role="sandbox_reviewer_test_role"`；
- `sandbox_test_organization_label="local_synthetic_sandbox"`；
- `sandbox_test_qualification_label="not_a_medical_credential"`；
- `sandbox_test_signature_scheme`、`sandbox_test_key_id`、`sandbox_test_signed_payload_digest`、`sandbox_test_signature`，仅用于工程完整性测试。

challenge 绑定：`graph_version`、namespace、`test_session_id`、thread/checkpoint/interrupt、state/formula revision、input/result/rule/dataset/review-render digest、256-bit nonce 的服务端摘要、issued/expiry time 和允许 action。明文 nonce 只在发出时返回一次，不进入 checkpoint、数据库或日志；challenge payload 只含引用、版本、digest 和合成展示摘要。

状态机：

```text
decided
  → create_single_use_challenge
  → interrupt(review_pending)
  → resume_request
       → atomic verify namespace/version/digests/nonce/expiry/action/signature
           ├─ any mismatch/replay/expired → resume_rejected
           └─ compare-and-swap issued→claimed→applied
                 ├─ lost race → resume_rejected
                 └─ confirm/reject/modify_fixture → append test review event
```

`Command(resume=...)` 只能携带 `resume_attempt_ref`，不能携带可信业务内容；恢复节点从 Domain Store 重读已经 claim 的决定和全部精确绑定。interrupt 前只允许版本化 formula/safety/explanation artifact、challenge/checkpoint 和 append-only audit/outbox，不得产生不可逆业务效果。没有当前有效 challenge/review 时，`sandbox_simulation_complete` 和任何 sandbox artifact export 均不可达。

### 7.6 L5-4：修改后全量重检与旧 review 失效

```text
modify_fixture accepted
  → create formula revision N+1
  → mark every review/challenge for revision N stale
  → full L5-1 deterministic recheck (not incremental reuse)
      ├─ rejected → blocked
      └─ decided → new result digest → new challenge → interrupt
```

不变量：

- 任一 formula/observation/safety profile/rule/dataset/graph/adapter/review DTO 版本或内容改变，旧 safety、explanation、challenge、review 和 completion eligibility 在同一 Domain 事务中全部失效；
- 修改不得删除、降级或覆盖旧 issue/run；旧记录 append-only 保留并标记 superseded/stale；
- 修改后必须运行全部规则，禁止仅重跑受影响规则；
- 新 result 未形成且新 Sandbox Review 未成功前，完成/导出路径不可达；
- 并发 resume 以数据库/持久层原子 compare-and-swap 保证仅一个成功；
- reject 只产生 sandbox 状态回退，不生成真实处方或医疗建议。
- record/done/export 的任何未来消费者每次都必须重查“当前 formula + 当前 safety passed + 当前 applied review”的 exact revision/digest 一致性；缓存、checkpoint 或仅有外键不能授权。

### 7.7 失效模式与处置

| 失效 | 必须行为 |
|---|---|
| schema/字段/解析错误 | 固定错误码、无原值、fail closed、规则零调用或结果不落“通过” |
| 版本或 digest 不一致 | 拒绝并记录预期/实际 digest 标识的安全摘要，不记录载荷 |
| rule bundle 缺失/未知 | 拒绝；不得回退到旧规则或 LLM 判断 |
| 持久化失败/事务冲突 | 不暴露 accepted decision；安全重试必须以同一 command ID 幂等 |
| explanation 失败 | 保留原 deterministic decision，标记 explanation unavailable |
| checkpoint/challenge 缺失 | resume 拒绝，不重建一个“等价” challenge |
| 过期/重放/跨会话/跨 namespace | 固定拒绝，nonce 不复活 |
| 并发 resume | 只有一个 CAS 成功，其余固定 conflict/replayed |
| 修改后旧 review 被引用 | 拒绝并指向新 revision，不接受风险继续 |
| 日志/审计序列化异常 | fail closed；不输出 payload、凭据、nonce、test signature 或异常链原文 |

### 7.8 当前实现只作为 RED 基线

- MainGraph 的 review 仍是 placeholder；不存在 L5 interrupt/resume 实现。
- Legacy `X-Doctor-Id`、`X-State-Version` 可省略，且 review 按时间选择“最新 safety run”，不能复用为 L5-3 信任边界。
- Legacy modify 直接重跑规则、写 review 并进入 record，尚无跨 safety/explanation/challenge/review/eligibility 的原子失效。
- `SafetyRuleEngine` 读取当前 DB 知识且安全运行记录缺 rule bundle/input/output digest，不能证明跨时间可重现。
- `medical_records.doctor_review_id` 可空，现有 export 也不是当前有效 review 的绝对 hard gate。
- ADR-005 的 `interrupt()` “不可绕过”是目标意图而不是已有保证；图、API、service、恢复、DB 和 export 必须逐边验证。

上述缺口在公共/临床/运行范围继续 NO-GO；它们不会被文档重解释为已经修复。L5-1 仅在不触碰这些路径的隔离 adapter 范围建立第一段工程证据。

## 8. 受控测试与验收矩阵

全部测试必须使用 §5 admitted synthetic manifest，默认禁止网络，并以 fake clock、fake signer、in-memory/fake rule port 运行。

| ID | 场景 | 预期证据 |
|---|---|---|
| DATA-01 | manifest 完整且 digest 匹配 | 准入；记录版本和 digest |
| DATA-02 | 来源不明、缺 generator/fixture 声明或疑似真实标识 | 测试收集前拒绝；不输出原值 |
| L5-1-01 | 正常 synthetic input | 精确 decision/issues/digest，append-only result 一条 |
| L5-1-02 | blocker/reject fixture | 后续 review/complete 不可达 |
| L5-1-03 | 缺字段、未知字段、版本不一致、坏 JSON、单位/数字解析错误 | 全部 fail closed；规则/外部调用次数符合零调用边界 |
| L5-1-04 | 同输入重复、跨进程/不同散列种子重复 | 结果逐字节相同，幂等 command 不重复写 |
| L5-1-05 | rule bundle/dataset digest 改变 | 产生新结果或拒绝，绝不复用旧结果 |
| L5-2-01 | 有效解释 | 每个声明一对一引用 issue/rule；原 result digest 不变 |
| L5-2-02 | 模型试图改 decision/severity/issues 或注入无依据内容 | verifier 拒绝解释；deterministic decision 不变 |
| L5-2-03 | 模型超时、异常、坏 schema | explanation unavailable；主结论不变 |
| L5-3-01 | 有效当前 challenge confirm/reject | 精确一次 resume；append-only test review 绑定全部版本/digest |
| L5-3-02 | 旧版本、重放、跨会话、跨 namespace、过期、错 nonce/signature | 全部固定拒绝；checkpoint 不推进 |

| L5-3-05 | 无当前有效 review | complete/export 路径结构不可达 |
| L5-4-01 | modify fixture | 新 formula revision；旧 challenge/review 全失效；全量规则重跑 |
| L5-4-02 | 修改后结果拒绝 | 再次 blocked/interrupt，不进入完成 |
| L5-4-03 | 规则/数据/graph/adapter 版本改变 | 旧 review 失效并重新评估全部规则 |
| OPS-01 | 日志、审计、错误 | 不含 fixture 原文、凭据、nonce、signature、Prompt 或异常 cause/context |
| OPS-02 | 回退 | sandbox flag 默认关闭；关闭后新执行不可达；既有测试记录不改写 |

### 8.1 性能与资源上限

L5-1 发布任务采用固定 64 项 synthetic formula 上限、最多 256 个 issue、输入/结果各不超过 256 KiB。隔离参考机上使用预热后的 1,000 次 in-memory/fake-rule 测量：adapter p95 `< 50 ms`、p99 `< 100 ms`，循环后 RSS 增长 `< 64 MiB`；结果必须记录 CPU、Python 版本、样本和统计方法。超过任一上限即拒绝，不截断后继续。

L5-2 explanation 输入最多 64 个 issue、输出最多 8 KiB；超过则 `explanation_unavailable`，不影响原裁决。L5-3 resume payload 最多 64 KiB，challenge 默认 15 分钟到期；测试中使用 fake clock，不等待真实时间。

### 8.2 缺陷严重度与停止条件

| 严重度 | 定义 | 处置 |
|---|---|---|
| P0 | 真实/可关联数据或有效凭据外泄，或可产生不可逆真实业务效果 | 立即停止 Goal，限制访问并升级外部门禁 |
| P1 | 可绕过 deterministic gate/review、fail open、旧 review 有效、多个 resume 成功、默认公开 | 验收前必须修复；不得发布下一任务 |
| P2 | 版本/digest/审计/日志/性能/资源边界 materially 不完整，可能误导或削弱可复现性 | 验收前必须修复；不得以残余风险直接接受 |
| P3 | 不影响边界的文案、可维护性或非阻塞一致性 | 记录并排队；不得含医疗许可误导 |

出现 P0/P1/P2、真实数据证据、未授权外部连接、无法归属 diff、测试使用未准入数据或必须扩大真实医疗范围时立即停止。
