## 2. Changes Summary

### 2.1 修 OP2 回归（health/llm lifespan 假设）— 紧急

**Problem**：OP2 commit `31295b7` 让 `main.py:/health/llm` 改为从 `request.app.state.gateway_client` 取共享实例；但 ASGI 测试客户端（`ASGITransport`）不跑 lifespan，`app.state.gateway_client` 永不存在。`uv run pytest` 暴露 **5 个 health_llm 测试全部 `AttributeError`**。

**Fix**：`/health/llm` 在 `getattr(request.app.state, "gateway_client", None)` 缺失时回退到临时 `ModelGatewayClient()` + 即时 `aclose()`，保证测试与无 lifespan 探测环境可用，生产（lifespan 永远跑）走共享路径不变。

```python
client: ModelGatewayClient | None = getattr(request.app.state, "gateway_client", None)
if client is None:
    client = ModelGatewayClient()
    try:
        checks = await client.health_check()
    finally:
        await client.aclose()
else:
    checks = await client.health_check()
```

**测得结果**：`tests/test_health_llm.py` 8 tests pass（原 5 fail）。

### 2.2 T1.2 `ReasoningAuthoritySnapshot` 进程缓存 + commit 后失效

**Problem**：reasoning 子图每个节点都 `repository.get_state(claim.session_id)`（[OP1 诊断](../03_agent性能优化/01-性能诊断报告.md) H1/H2），单 claim 最多 7 处 DB round-trip。

**Fix**（三段）：

**(a) 进程级缓存** `_REASONING_AUTHORITY_CACHE: BoundedTTLCache[uuid.UUID, ReasoningAuthoritySnapshot]`（`langgraph_reasoning.py`）：

```python
_REASONING_AUTHORITY_CACHE: BoundedTTLCache[uuid.UUID, ReasoningAuthoritySnapshot] = BoundedTTLCache(
    max_size=256, ttl_seconds=300,
)

async def _current_authority(repository, session_id, *, claim_id=None):
    if claim_id is not None:
        cached = _REASONING_AUTHORITY_CACHE.get(claim_id)
        if cached is not None and cached.session_id == session_id:
            return cached
    async with measure("reasoning.get_state"):
        state = await repository.get_state(session_id)
    authority = await repository.get_reasoning_authority(session_id, state.state_version)
    if authority is not None and claim_id is not None:
        _REASONING_AUTHORITY_CACHE[claim_id] = authority
    return authority
```

**(b) 关键正确性修复（precheck 后命中 vs commit 后失效）**：
工作树初版直接上缓存会引入版本错位 bug——`draft_syndrome` commit 后 state_version 从 N 跳到 N+1，下游 `build_formula_context` 命中缓存仍拿到 N → `formula.input_payload.state_version=N` → `_commit_artifact_payload` 撞 `STATE_VERSION_CONFLICT`。本阶段在 `_commit_syndrome_artifact` 与 `_commit_formula_artifact` 提交成功后**显式 pop 缓存**：

```python
# in _commit_syndrome_artifact / _commit_formula_artifact
_REASONING_AUTHORITY_CACHE.pop(claim.id, None)
```

**Focus 测试覆盖**（`tests/test_l4_4_reasoning_authority_cache.py`）：
- `test_current_authority_cache_hit_avoids_repeated_db_round_trips`：mock 仓库，3 次同 claim_id 调用仅触发 1 次 DB。
- `test_authority_cache_must_be_invalidated_after_state_version_bump`：模拟 N→N+1 commit，pop 后下次读取必须拿到 N+1。
- `test_commit_helpers_invalidate_authority_cache_source_contract`：源码契约（`inspect.getsource`），防止后续重构误删 pop 行。

**(c) Histogram**：`reasoning_get_state` 直方图（`xuanhu_reasoning_get_state_seconds`，label-free）注册到 `metrics.py:measure("reasoning.get_state")`，与已有 7 个 histogram 同等待遇。

**预期收益**（per plan）：single-claim DB round-trip 10+ → 1-2，DB 往返降 ~60-70%。需真实问诊流量采集 after P95 填 99 文档。

### 2.3 T1.3 intake `_INTAKE_COMPUTATION_CACHE`（T1.3/T1.4 合并落地）

**Problem**：`run_intake_gates_node` 算一次 `_compute_intake_from_claim`（reduce + 3 DB 查询 + classify trace），紧接 `_finalize_intake_route` 四路由（ready/incomplete/conflict/manual）再算一次；LLM 调用已有 `_INTAKE_OUTPUT_CACHE` / `_CLASSIFY_TRACE_CACHE` 去重，但 reduce + get_state + progress + pending_safety_dimensions 三个 DB round-trip 仍重复。

**Fix**：进程级 `_INTAKE_COMPUTATION_CACHE: BoundedTTLCache[uuid.UUID, _IntakeComputation]`：

- `run_intake_gates_node` 算完后：`_INTAKE_COMPUTATION_CACHE[claim.id] = computation`
- `_finalize_intake_route` 优先读缓存，缺失（不同进程 resume / 进程内首次调用）回退到原 `_compute_intake_from_claim`，不破坏现有契约。
- 清理走 TTL（max_size=256 / ttl=300s）兜底，未显式在 6 个 `_INTAKE_OUTPUT_CACHE.pop` 站点同步清理（开销小、TTL 足够）。

**清理工作区 dead code**：删除 `_finalize_intake_route` 中半成品 `cached_disposition` / `cached_classify_trace` 校验块（原代码读 gates payload 后 `pass` 走 fall-through，无实际效果），替换为真正的 cache-read path。

### 2.4 T3.1 `_vector_search` 用 `asyncio.to_thread` 包 `milvus.search`

**Problem**：`pymilvus` 同步阻塞 `milvus.search(**search_params)`（[retriever.py:423](../rag/retriever.py#L423)），包裹在 async 函数里直接阻塞事件循环；并发请求 → 向量检索串行化。

**Fix**：

```python
# retriever.py: _vector_search
results = await asyncio.to_thread(milvus.search, **search_params)
```

`asyncio.to_thread` 是 pymilvus 在无成熟 async 接口时的最低侵入升级。同款处理 `_check_milvus` / `_check_milvus_collection` 中 `client.list_collections()` / `client.describe_collection(...)`。

**预期收益**（per plan）：并发请求吞吐上限打开（"单线程串行向量检索" → "并行 to_thread"）。

### 2.5 T3.2 + T3.3 共享 RAGRetriever（单例）+ gRPC 通道复用

**Problem**：`_rag_retriever()`（[langgraph_reasoning.py:291](../services/langgraph_reasoning.py#L291)）每 stage `RAGRetriever()` 新建；`_get_milvus_client` 懒初始化但每个实例独立一次 → Milvus client 每节点重建 gRPC channel。辨证+开方两阶段合计 6 次/推理 → 6 个 gRPC channel 池。

**Fix**：模块级共享 `_shared_rag_retriever: RAGRetriever | None` + `get_shared_rag_retriever()` / `reset_shared_rag_retriever()`：

```python
_shared_rag_retriever: RAGRetriever | None = None

def get_shared_rag_retriever() -> RAGRetriever:
    global _shared_rag_retriever
    if _shared_rag_retriever is None:
        _shared_rag_retriever = RAGRetriever()
    return _shared_rag_retriever
```

`_rag_retriever()` 改为 `return get_shared_rag_retriever()`。

**Race 容忍**：多协程/线程首次调用可能各构造一个 RAGRetriever，但 `RAGRetriever.__init__` 不做 I/O（httpx.AsyncClient 延迟建连、Milvus 延迟实例化），未被引用的实例随 GC 释放；最后持久化的实例即为"共享单例"。未引用实例不触发任何外部资源（无 httpx 连接、无 Milvus 客户端）。

**预期收益**（per plan）：连接建立 gRPC channel 每节点重建 → 进程单例。

### 2.6 T3.5 + T3.6 M1 output_fields 含 content + 回填优先 Milvus

**Problem**：向量命中 `VectorHit.content_snippet` 为空时，`_backfill_content_snippets` 单独 PG round-trip 回填（[retriever.py:560-597](../rag/retriever.py#L560)），单次 RAG 多一次 DB 查询。

**Fix（先采样后落地）**：

**预检采样**（`knowledge_chunks` 中 `deleted_at IS NULL AND embedding_status='done'` 共 3799 行）：

| metric | value |
|---|---|
| avg_len | 341 chars |
| p50 | 324 |
| p95 | 620 |
| p99 | 783 |
| max | 800 |

集合膨胀 ~3799 × 0.8KB ≈ 3MB（worst case 800 chars × 4 字节中文 UTF-8 ~3.2KB），与现状 ~1.3MB embedding 维度（768 float × 4B × 3799 ~11.6MB）相比 **< 30%**。**M1 安全落地**。

**实现**：
- `VectorHit` schema 加可选 `content: str = ""`（[schemas.py](../rag/schemas.py)）。
- `retriever.py` `output_fields` 加 `"content"`，回填到 `VectorHit.content`。
- `merge_deduplicate` 优先用 `vh.content`（M1），缺失留空给 `_backfill_content_snippets` 回填 PG（向后兼容旧 collection）；同一 chunk 同时命中向量+全文时仍以全文内容覆盖（全文 snippet 通常更完整）。
- 旧 collection 无 `content` 字段时 `entity.get("content")` 返 None → `str(None)` = `"None"`，已用 `entity.get("content", "")` 默认空串避免污染。

**Focus 测试**（`tests/test_rag_shared_retriever.py`）：
- `merge_deduplicate_prefers_milvus_content_over_pg_backfill`：`VectorHit.content` 非空时直接进 `MergedHit.content_snippet`。
- `merge_deduplicate_empty_vector_content_falls_back_to_pg_backfill`：空 content 留空给 PG 回填。
- `merge_deduplicate_fulltext_overrides_milvus_content_when_both_hit`：同 chunk 全文覆盖。
