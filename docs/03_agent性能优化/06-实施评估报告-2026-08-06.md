## 1. P0 · Modification RAG 差异化

### 真实后端评测结果（真实 Milvus，xuanhu_knowledge_v4，3799 entities）

| 用例 | Formula 源 | Modification 源 | 重叠率 | 独有证据 | Verdict |
|------|-----------|----------------|--------|---------|---------|
| 风寒束表证—麻黄汤 | case+formula | case | **0%** | 8 | ✅ PASS |
| 脾虚湿困证—参苓白术散 | case | case+herb | **0%** | 8 | ✅ PASS |
| 肝郁气滞证—柴胡疏肝散 | case | case | **0%** | 8 | ✅ PASS |

### 关键发现

1. **0% 证据重叠** — Modification RAG 在所有 3 个场景下返回与 Formula RAG 完全不同的证据集合。P0 的核心目标（消除两次 RAG 检索的高度重叠）已达到。

2. **Source type 正确隔离** — Modification 从未返回 "formula" 类型证据（因为 MODIFICATION_PRIMARY_SOURCES = `("herb", "case")` 不含 formula）。脾虚湿困案中 Modification 额外返回了 "herb" 类型（白术），这正是加减阶段需要的中药特性知识。

3. **延迟更优** — Modification RAG 延迟约 148-634ms，比 Formula RAG（143-2387ms）更快或持平，因搜索空间更小（不含 formula 库）。

## 3. P2 · 辨证 Query LLM 改写

### 真实后端评测结果（真实 LLM: mimo-v2.5 + 真实 Milvus）

| 用例 | 原始 query（key=value） | 改写后（医学叙事） | 改写延迟 | 检索差异 |
|------|----------------------|-------------------|---------|---------|
| 风寒咳嗽案 | `chief_complaint=受凉后咳嗽三天；cough=咳嗽...` | LLM 改写为医学叙事 | ~7.4s | Top-5 完全不同 |
| 心脾两虚失眠案 | `chief_complaint=失眠多梦三个月；palpitations=心悸健忘...` | LLM 改写为医学叙事 | ~4.7s | Top-5 完全不同 |
| 脾阳虚泄泻案 | `chief_complaint=大便溏稀两个月；appetite=食少...` | LLM 改写为医学叙事 | ~4.3s | Top-5 完全不同 |

### 关键发现

1. **LLM 改写有效** — 改写后的 query 产生的检索结果与原始 key=value query 完全不同，验证了"结构化 key=value 与医学叙事处于不同语义空间"的假设。

2. **延迟偏高** — 改写延迟 4.3-7.4s（mimo-v2.5），远超 `rag_query_rewrite_timeout_seconds` 默认值 3.0s。建议：
   - 生产环境使用轻量快速模型（如 qwen3.7-flash 或更小模型）以控制延迟 < 1s
   - 或启用改写缓存（同 session 内 observations 变化不大时可复用）

3. **功能开关已就绪** — `rag_query_rewrite_enabled=False` 默认关闭，配置项完备。建议找轻量模型后开启 A/B 评测。

## 4. Reranker 升级

### 真实后端评测结果（Cross-Encoder: jina-reranker-m0 @ dmxapi）

| Query | MVP Top-3 | CE Top-3 | 重叠率 | CE 延迟 |
|-------|----------|---------|--------|---------|
| 风寒咳嗽加减 | 风寒束表证、麻黄细辛附子汤、三方合用加味 | 风寒束表证(0.98)、**小青龙汤**(0.90)、**麻杏石甘汤**(0.89) | 1/3 | 2229ms |
| 胸胁胀痛方剂 | 肝郁气滞(段1)、肝郁气滞(段2)、大柴胡汤合逍遥散 | 肝郁气滞段1(0.97)、**大柴胡合枳实薤白桂枝**(0.96)、肝郁气滞段2(0.96) | 2/3 | 1220ms |
| 脾胃虚弱穴位 | 理中汤、白术、黄芪 | **蜂针疗法医案**(0.89)、**黄芪建中汤医案**(0.72)、白术(0.70) | 1/3 | 1113ms |

### 关键发现

1. **Cross-Encoder 重排效果显著** — 3 个 query 中 top-3 排序均发生实质变化：
   - 风寒咳嗽案：CE 将 MVP 排名靠后的"小青龙汤"和"麻杏石甘汤"提到 top-3（更相关于咳嗽加减）
   - 脾胃虚弱案：CE 将"理中汤"从 #1 移到 #5 外，将临床医案提到 #1（因为 query 问的是穴位而非方剂）

2. **分数区分度大幅提升** — CE 分数范围 0.68-0.98（区分度 0.30），MVP 分数范围 0.59-0.68（区分度 0.09），CE 区分度是 MVP 的 3 倍+。

3. **延迟可接受** — CE 延迟 1.1-2.2s（含网络往返），与一次 Milvus ANN 检索（~150ms）叠加后总延迟 ~1.3-2.4s，在可接受范围。

4. **dmxapi 使用 Cohere 格式** — API 格式为 `{"model":"...","query":"...","documents":["..."]}` 而非 Jina 的 `input: [{query, document}]`。已修复 `_call_reranker_api` 适配。

5. **LLM Reranker 解析失败** — LLM Reranker 输出的分数全部为 0（解析失败），降级为 MVP 排序。LLM 返回格式不稳定，暂不推荐使用。

### API 格式修复

`_call_reranker_api` 已从 Jina-style 更新为 Cohere-style：

```python
# 修复前（Jina-style，dmxapi 返回 422）
payload = {"model": model, "input": [{"query": q, "document": d} for d in docs]}

# 修复后（Cohere-style，dmxapi 返回 200）
payload = {"model": model, "query": query, "documents": docs, "top_n": len(docs)}
```
