## 2. 防回归门禁

### 2.1 自动化回归

每个阶段提交前必须通过：

- `pytest` 全量，通过率不降
- `vitest` 全量（前端本期基本不动，但保险跑一遍）
- `tests/golden/test_langgraph_performance_baseline.py` 仍 `p95 < 5000ms`（不退化）

### 2.2 lazy=raise 触发检测（OP1 专项）

OP1 引入 snapshot 后，若某节点未被 selectinload 覆盖而访问关系，会 `lazy="raise"` 抛错。CI 加检测：

- 在每次 reasoning/intake 路径测试里断言无 `RelationshipLazyLoadError`（或 SQLAlchemy 等价异常）被触发。
- 若触发，说明 snapshot 路径漏了 eager load，必须补 T1.5。

### 2.3 checkpoint bloat 检测（OP1 专项）

- 比较改造前后，单次 graph 运行的 `checkpoint` 表行平均大小不显著增长（`snapshot` 字段必须 transient 不进序列化）。
- 用 `select avg(length(pg_column_size(checkpoint_blob)))` 采样。

### 2.4 structured 解析成功率（OP2 专项 T2.6）

关闭 legacy structured fallback 前后对比：
- 指标 = `(成功 structured 解析次数) / (chat_structured 调用总数)`
- 不允许下降超过 1 个百分点。
- 若下降，保留 fallback 不关，仅做池化 + cache。

### 2.5 向量召回质量（OP3 专项）

- 并发 N（如 8）路 `rag.vector_search` 的 wall-clock 总延迟 before/after 对比（应显著改善，因不再阻塞事件循环）。
- 召回 hits 数不变（M1 落地后 output_fields 含 content，hits 仍一致；若 T3.5 测得 chunk 超大降级，则 M1 不落地，hits 由 PG 回填保证一致）。
