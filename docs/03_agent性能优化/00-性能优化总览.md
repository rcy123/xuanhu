## 3. 优化范围圈定

三路调研共发现 7 项高 ROI + 11 项中 ROI 缺陷（详见 [01-性能诊断报告.md](01-性能诊断报告.md)）。按"作品集展示价值 × 落地可行性"，**本次优化只做以下四块**：

| 编号 | 优化块 | 关联缺陷 | 展示价值 | 预期收益 |
|---|---|---|---|---|
| **OP1** | 状态下推子图：DomainState/intake 计算结果随 `XuanhuGraphState` 流转，节点间不再重复查库 | H1 H2 M10 | 懂 LangGraph state 流转 | 单 claim DB round-trip 降 60%+ |
| **OP2** | 网关连接池化 + embedding 缓存 | H3 H4 M5 | 经典高并发优化 | 握手开销 ×N → 1；embedding RTT 命中即跳 |
| **OP3** | Milvus 同步调用 `to_thread` + 共享 client | H5 H6 M1 | 解决事件循环阻塞 | 并发吞吐上限打开 |
| **OP4** | per-stage 延迟埋点 + Prometheus histogram | H7 | 可观测性即工程能力 | P50/P95 可量化，优化效果可证明 |

**不在本次范围**（中 ROI 第二批，留作后续)）：
- M2 `_load_herb_normalizer` LRU、M3 `AgentRuntime` 单例、M4 recorder 合并、M6 子图节点 `asyncio.gather`、M7 `selectinload`、M8 SSE 背压、M9 outbox LISTEN/NOTIFY、M11 Redis max_connections——详见诊断报告，本期仅在文档里留 TODO。

**显式不做**（真依赖,非缺陷）：
- base_formula → modification 串行(医学必须)
- 单轮 intake 两段模型串行(composer 须等 extraction 缺口)
- command_router(已最优)、Send API(业务不需要)、并行同 prompt 取最佳(质量要求高)
