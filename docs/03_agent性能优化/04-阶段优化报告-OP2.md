## 3. 改动详解

### 3.1 T2.1 — httpx.Limits 连接池上限（`app/core/gateway.py`）

**问题**：`b1c5223` 已将 `httpx.AsyncClient` 提为实例成员 `self._client`，但未配置 `Limits`，连接池规模与 keepalive 行为完全走 httpx 默认（`max_connections=None` 无上限，高并发下可能压垮网关侧）。

**改动**（[gateway.py:104-115](app/core/gateway.py#L104)）：
```python
_limits = httpx.Limits(
    max_connections=64,
    max_keepalive_connections=16,
    keepalive_expiry=30.0,
)
self._client = httpx.AsyncClient(
    timeout=httpx.Timeout(self._timeout, connect=10.0),
    limits=_limits,
)
```

- `max_connections=64`：单进程并发连接上限，防止突发流量打爆网关。
- `max_keepalive_connections=16`：keep-alive 池容量，复用 16 条空闲连接。
- `keepalive_expiry=30.0`：空闲连接 30s 后回收，平衡复用率与连接新鲜度。

### 3.2 T2.2 — lifespan 托管客户端生命周期（`app/main.py` + `app/core/gateway.py`）

**问题**：原 `ModelGatewayClient` 在 `/health/llm` 端点每次新建实例，连接池随请求创建/销毁，lifespan 无关闭钩子，进程退出时连接泄漏。

**改动**：
1. `ModelGatewayClient` 新增 `aclose()` 方法与 `client` property（[gateway.py:117-128](app/core/gateway.py#L117)）：
   ```python
   async def aclose(self) -> None:
       await self._client.aclose()
   ```
2. `app/main.py` lifespan 中构造并挂载共享实例（[main.py:49-52](app/main.py#L49)）：
   ```python
   gateway = ModelGatewayClient()
   app.state.gateway_client = gateway
   ```
   退出时在 `finally` 最内层调用 `await gateway.aclose()`（[main.py:119-120](app/main.py#L119)）。
3. `/health/llm` 改为从 `app.state` 复用，不再临时 `ModelGatewayClient()`（[main.py:230-231](app/main.py#L230)）。

类比 `shared_langgraph_runtime` 的"启动构造 / 退出关闭"模式。

### 3.3 T2.4 / T2.5 — Embedding 缓存（`app/rag/embedding_cache.py` + `retriever.py` + `config.py`）

**问题**（[02-优化方案设计.md §2.2(b)](02-优化方案设计.md)）：`_vector_search` 每次 `await self._gateway.embed([query], ...)`，无缓存。问诊场景下同一 query 文本（如主诉"咳嗽一周"）在 reasoning 多节点重复出现，重复消耗网关 RTT（50–200ms）。

**改动**：
1. **新增 `app/rag/embedding_cache.py`** — 模块级 `get_embedding` / `set_embedding` / `clear_cache`：
   - key = `embed:` + `sha1(query_text)`（[embedding_cache.py:27-33](app/rag/embedding_cache.py#L27)）
   - value = JSON 序列化的 `list[float]`
   - store = Redis（复用 `app.core.redis.get_redis` 单例）
   - TTL 由 `Settings.embedding_cache_ttl_seconds` 控制（默认 3600s，传 0 禁用）
   - 只缓存 **query 侧** embedding，不缓存文档侧（文档侧是离线 sync 脚本产物，在线不重算）

2. **`retriever._vector_search` 接入缓存**（[retriever.py:393-406](app/rag/retriever.py#L393)）：
   ```python
   cached = await get_embedding(query)
   if cached is not None:
       query_vector = cached            # 命中 → 跳过网关调用
   else:
       embeddings = await self._gateway.embed([query], trace_id=trace_id)
       query_vector = embeddings[0]
       await set_embedding(query, query_vector)   # 回填
   ```
   注意 `set_embedding` 仍在原 `measure("rag.embed")` 之外，缓存命中路径**完全不触发** `rag.embed` 埋点——histogram 可直接反映"被缓存抹掉的网关调用数"。

3. **`config.py` 新增配置**（[config.py:158-160](app/core/config.py#L158)）：
   ```python
   embedding_cache_ttl_seconds: int = Field(
       default=3600, ge=0, description="Embedding 向量缓存 TTL（秒），0=不缓存"
   )
   ```

### 3.4 测试脚本扩展（`scripts/perf_benchmark.py`）

新增 `test_embedding_cache_hit()`，绕过 HTTP 直测 Redis 缓存层：
- 第 1 次 miss → 真实 `gateway.embed` 网关调用 + 显式回填
- 第 2 次 hit → Redis 读取
- 输出 `miss / hit / hit_ok / approx_speedup`

## 5. 风险与遗留

### 5.1 T2.6 legacy structured fallback — 未关闭

计划 T2.6 要求审查 `chat_structured` 全调用点、强制 `max_requests=1`、移除 legacy 路径的 `json_object` fallback。**本阶段未落地**，原因：

- L2 runtime（`app/agent_runtime/runtime.py:461-462`）已对生产路径强制 `kwargs["max_requests"] = 1`，触发 `gateway.py:646-647` 的 `if max_requests is not None: break`，**生产 bounded 路径已天然不触发 fallback**（[gateway.py:519-521](app/core/gateway.py#L519) 注释已说明）。
- legacy 路径（`max_requests=None`）的 fallback 是"不对接 runtime 的旧调用"的安全网；按设计文档 [02 §2.2(c)](02-优化方案设计.md) 要求在**预发布跑回归对比 structured 解析成功率**后才可关闭，否则可能让依赖 fallback 提高解析率的旧路径成功率下降。
- 这项属于"破坏性变更"，需独立验证轮次，不应混入本池化+缓存阶段。

**遗留**：单独开一轮做 T2.6 的回归对比（99 文档 §2.4 门禁），确认解析成功率不降 1pp 后再关。

### 5.2 Redis ACL 与离线验证缺口

本地 Redis 启用 ACL 导致 `test_embedding_cache_hit()` 无法在当前环境跑出真实 hit 数字。生产/预发布环境配好 `REDIS_URL` 后需补跑该测试以量化命中率。

### 5.3 共享 client 与健康检查的复用边界

`/health/llm` 现复用 `app.state.gateway_client`。若后续有"轻量探针不应占用主连接池 slot"的需求，可改为独立短超时 client；当前复用是预期行为（每进程单例正确）。
