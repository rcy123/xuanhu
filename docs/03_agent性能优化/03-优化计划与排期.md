## 2. 依赖与串并行

```
T0（埋点）── 必须最先，无依赖
   │
   ├─ T1（状态下推）─ 依赖 T0 完成才能量化
   ├─ T2（网关池化）─ 依赖 T0
   └─ T3（Milvus异步）─ 依赖 T0
        │
        T1/T2/T3 之间无强依赖，可并行；但若单人推进，按 T1→T2→T3 顺序
   │
   T4（回归对比）─ 依赖 T1+T2+T3 全完成
```

> 单人推进建议串行：T0 → T1 → T2 → T3 → T4。若多人，T1/T2/T3 在 T0 后可分人并行。

## 4. 风险与回退

| 风险 | 缓解 |
|---|---|
| OP1 snapshot 进 checkpoint 导致 bloat 或反序列化失败 | snapshot 字段标 transient 不进 checkpoint；resume 路径重新触发入口加载 |
| OP1 snapshot 让某节点 lazy=raise 抛错 | T1.5 强制为本期路径加 selectinload；CI 加 lazy 触发检测 |
| OP2 关闭 legacy fallback 后 structured 解析率下降 | T2.6 先在预发布跑回归，对比解析成功率；若下降则保留 fallback 不关 |
| OP2 httpx 单例在 gunicorn 多 worker 下每进程一个 client | 预期行为，每进程单例正确，不需跨进程 |
| OP3 to_thread 占用线程池默认容量 | 默认 asyncio 线程池上限够用；并发极高时需调 `loop.set_default_executor` |
| OP3 output_fields 含 content 致 Milvus collection 膨胀 | T3.5 先测 chunk 平均大小；超大（超预设阈值）则该子项降级为"仅做 to_thread+共享client，M1 不落地"，回退到原 PG 回填路径 |
| 埋点本身增加开销 | prometheus histogram 观察开销 < 0.01ms；可接受 |

回退：各阶段改动均不破坏对外契约，出问题可单独 revert 该阶段 commit，互不影响。
