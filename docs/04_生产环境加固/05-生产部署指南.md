# 生产部署指南（阶段 3 基础设施加固配套）

> 适用：医院/机构内网单机部署（Docker Compose）。前提前置完成阶段 1-2 的
> 环境变量配置（JWT_SIGNING_KEY / XUANHU_AUTH_ENABLED=on 等）。

---

## 1. 生成强凭据

```bash
./scripts/gen-secrets.sh --include-jwt
```

输出到 stdout（**不会写文件**），把结果复制进生产 `.env`（文件权限收紧：
`chmod 600 .env`，仅运行账户可读）。该命令一次性生成：

| 变量 | 说明 |
|---|---|
| `POSTGRES_PASSWORD` | 强随机 base64 |
| `REDIS_PASSWORD` | 强随机 base64 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 强随机 |
| `JWT_SIGNING_KEY` | 强随机（`--include-jwt` 首次初始化时生成） |

> `MODEL_GATEWAY_API_KEY` 等网关密钥不在此生成——需从各网关后台签发，
> 轮换周期 90 天（见附录「上线后持续安全基线」）。

## 2. 启动中间件（生产形态）

```bash
docker compose -f docker-compose.yml up -d
```

**不做任何端口映射到 host**——PG/Redis/MinIO/Milvus 只在 Compose 内网可
达。验证：`netstat -tlnp` 在 host 上应看不到 5432/6379/9000/9001/19530。

本地开发需要端口时用 `docker compose up -d`（自动加载
`docker-compose.override.yml` 加回端口与默认凭据）。

## 3. 启动 API（反向代理模式）

```bash
# API 只监听回环，TLS 由 nginx 终止
API_HOST=127.0.0.1 uv run xuanhu-api   # 或容器部署，expose 8000
```

- 生产启动守卫（`APP_ENV=production` + `XUANHU_PROD_SECRET_GUARD=true`）：
  任一密钥缺失/占位符/默认值（含 `xuanhu_dev`、`minioadmin`、`sk-change-me`）
  → **启动即失败**，日志指明不合规变量。
- 模型白名单（`MODEL_WHITELIST`）：生产必填，逗号分隔允许的模型名；
  为空 → 启动失败。
- CORS（`CORS_ALLOWED_ORIGINS`）：填入前端真实域名，禁止 `*`。

## 4. 反向代理终止 TLS

```bash
# 将模板复制到 nginx，替换 server_name 与证书路径
cp deploy/nginx/xuanhu.conf /etc/nginx/conf.d/xuanhu.conf
# 证书放 /etc/nginx/ssl/{xuanhu.crt,xuanhu.key}（院内 CA 或自签）
```

- access log 不记 query string（SSE `?token=` 不落盘）。
- SSE 已配置 `proxy_buffering off` + 3600s 超时。

## 5. 验收清单（阶段 3）

- [ ] `netstat -tlnp` host 上无 5432/6379/9000/9001/19530 监听。
- [ ] `APP_ENV=production` 且 `POSTGRES_PASSWORD=xuanhu_dev` → API 启动失败。
- [ ] `curl -k https://xuanhu.<host>/api/v1/health` → 200；直连 8000 被拒。
- [ ] nginx access log 无 query string。
- [ ] MinIO console 9001 在 host 不可达。

## 6. 回退

- 凭据守卫：`XUANHU_PROD_SECRET_GUARD=false` 可临时关闭（需事后审计）。
- 中间件端口：本地用 `docker compose.override.yml` 找回；生产不允许。
