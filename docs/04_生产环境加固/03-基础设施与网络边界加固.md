# 阶段 3 · 基础设施加固 + 网络边界

> 状态：已实施（待安全评审签字后上线）
> 上线阻断级别：**should**（内网定级下调；但 H3/H5 仍需处理）
> 前置依赖：阶段 1（API 认证保证即便端口暴露也有补救层）
> 关联缺陷：H2 / H3 / H5 / H8 / M4

---

## 1. 目标

修复基础设施层面的默认凭据、端口暴露、明文传输问题。本阶段以**运行环境配置**与**Docker Compose 改造**为主，业务代码改动极少。

**完成定义**：

1. PostgreSQL / Redis / MinIO 使用强随机凭据，无任何默认密码。
2. 中间件端口仅在 Docker 内网可达，不映射到 host。
3. 进入应用的流量统一经反向代理终止 TLS，后端只监听内网。
4. Milvus 向量检索链路在内网明文可接受，但 MinIO 凭据非默认。

---

## 2. 中间件凭据加固（H3 + H5）

### 2.1 Docker Compose 改造

当前 `docker-compose.yml` 把 PG/Redis/MinIO/Milvus 全部 `ports` 映射到 host。生产改造：

```yaml
services:
  postgres:
    # 删除 ports 映射；仅 expose 内部
    expose:
      - "5432"
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}   # 无 :-default，强制必填
```

**关键原则**：

- **删除**所有中间件的 `ports:` 映射，改为 `expose:`（仅 Compose 内网可达）。
- API 后端容器加入同一 Compose 网络，通过服务名访问中间件。
- 仅 API 后端与反向代理的端口对外，其余中间件全内网。

### 2.2 强凭据生成与注入

新增 `.env.example` 项全部移除默认密码值（保留 `:-default` 的仅本地开发）：

```bash
# 必填，无默认值；启动脚本生成
POSTGRES_PASSWORD=<openssl rand -base64 24>
REDIS_PASSWORD=<openssl rand -base64 24>
MINIO_ACCESS_KEY=<openssl rand -hex 12>
MINIO_SECRET_KEY=<openssl rand -base64 24>
JWT_SIGNING_KEY=<openssl rand -base64 48>   # 阶段 1 已引入
```

提供 `scripts/gen-secrets.sh`：一键生成一组强凭据，输出到 stdout 供复制到生产 `.env`。**禁止**该脚本直接写文件（避免误把密钥落磁盘）。

### 2.3 占位符守卫

阶段 1 已实现 API Key 占位符 fail-fast。本阶段扩展到**所有**密钥类环境变量（POSTGRES_PASSWORD、REDIS_PASSWORD、MINIO_SECRET_KEY 等）：`APP_ENV=production` 时，若任一为空、为占位符、或匹配 `minioadmin`/`xuanhu_dev` 等已知默认值，启动即失败。

校验集中在 `app/core/config.py` 新增 `validate_production_secrets()`，lifespan 启动时调用。

## 3. 网络边界（H2 + M4）

### 3.1 API 监听地址

当前 `.env` 的 `API_HOST=0.0.0.0`。生产改为：

- **方案 A（推荐，反向代理模式）**：`API_HOST=127.0.0.1`，前置 Nginx/Caddy 终止 TLS 后转本机回环。最稳。
- **方案 B（容器模式）**：API 容器 `API_HOST=0.0.0.0` 但 Compose `expose` 不 `ports`，仅反向代理容器可访问。

`.env.example` 默认值改为 `127.0.0.1`，并把 `0.0.0.0` 标注为"仅开发用"。

### 3.2 反向代理终止 TLS

提供 `deploy/nginx/xuanhu.conf` 模板：

```nginx
server {
    listen 443 ssl http2;
    server_name xuanhu.<hospital>.intranet;

    ssl_certificate     /etc/nginx/ssl/xuanhu.crt;
    ssl_certificate_key /etc/nginx/ssl/xuanhu.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;

    # /health 系列与 /metrics/outbox 不记 query string
    log_format no_query '$remote_addr - $request_method $uri $status';
    access_log /var/log/nginx/xuanhu.log no_query;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        # SSE
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

> **M4 缓解**：uvicorn 本身不配 SSL；TLS 由 Nginx 终止。证书由院内 CA 签发或自签（内网可接受自签，但需在客户端预置信任）。

### 3.3 minIO 控制台不对外

MinIO 容器的 `9001` 控制台端口在生产**完全不暴露**（删除 `ports:`，仅 `expose:`）。控制台访问通过 `kubectl exec`/ssh 隧道，不进常规网络。

## 4. Milvus TLS（H8，内网可降级）

### 4.1 决策

内网部署下，Milvus 与 API 同 Compose 网络，明文传输风险等级 LOW。**MVP 不强制 Milvus mTLS**，但需：

- Milvus 端口不暴露到 host（已在 §2.1 处理）。
- MinIO→Milvus 间也不出容器网络。
- 文档记录该决策与未来升级路径（若 Milvus 跨机部署，再开 mTLS）。

### 4.2 升级路径

预留 `MILVUS_USE_TLS` 开关（默认 false）。若设 true，`MilvusClient` 构造使用 `https://` + CA 证书路径。本阶段不实现代码，仅在 `app/services/health.py` 与 `app/rag/retriever.py` 留 TODO 注释指向本文档。

## 5. Docker Compose 健康检查与资源限制

现状已有 healthcheck，本阶段补充生产部署必选项：

```yaml
postgres:
  deploy:
    resources:
      limits:
        memory: 2g
  logging:
    driver: json-file
    options:
      max-size: "100m"
      max-file: "5"
```

为所有中间件加 `logging` 限制，防止日志撑爆磁盘。API 后端容器同样加。

## 7. 验收

- [ ] `docker compose up` 生产模式后，`netstat -tlnp` 在 host 上看不到 5432/6379/9000/9001/19530 任一端口监听。
- [ ] `APP_ENV=production` 且 `POSTGRES_PASSWORD=xuanhu_dev`（默认值）→ API 启动失败，日志提示哪个变量不合规。
- [ ] `curl https://xuanhu.<host>/api/v1/health` 返回 200；`curl http://xuanhu.<host>:8000/api/v1/health`（直连后端）应被防火墙/Nginx 拒绝。
- [ ] Nginx access log 不含 query string（`?token=...` 不会泄露）。
- [ ] MinIO console 9001 端口在 host 不可达。

## 8. 风险与回退

| 风险 | 缓解 |
|---|---|
| 中间件不暴露端口后，本地调试不便 | 提供 `docker-compose.override.yml`（开发用），自动加回 ports 映射；生产 compose 用 `-f docker-compose.yml` 不带 override |
| Nginx 配置错误导致全站 502 | 灰度在预发布环境先跑；保留直接连后端的应急通道（限内网 IP 白名单） |
| TLS 证书过期 | 监控告警加证书剩余天数检查（阶段 4） |
| validate_production_secrets 过严阻断正常启动 | 错误信息精确到具体变量与不合规原因；本地 `APP_ENV!=production` 不触发 |

回退：凭据类守卫同样走环境开关 `XUANHU_PROD_SECRET_GUARD`，紧急时可关闭，但需事后审计。
