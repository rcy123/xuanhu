> 状态：方案稿
> 上线阻断级别：**should**
> 前置依赖：阶段 1-3 完成
> 关联缺陷：H6 / H9 / M1 / M2 / M3 / M5

---

## 1. 目标

阶段 1-3 建立了"身份、数据、网络"三道边界。阶段 4 补齐运行态的**纵深防御**：限流、接口暴露面收敛、跨域与 CSRF、配置白名单、运行态开关门禁。这些缺陷单独看均为 MEDIUM，但叠加后构成生产运行的可靠性底线。

**完成定义**：

1. 每医师每分钟对 advance/login 等敏感接口有调用上限，超限返回 `429`。
2. 生产环境 `/docs` 与 `/openapi.json` 关闭。
3. CORS 仅允许已知前端来源。
4. 模型名接入白名单，防止配置被篡改指向任意端点。
5. `langgraph_product_ready` 等关键开关有"启动快照 + 偏离告警"。

## 2. 速率限制（H6）

### 2.1 方案

使用 **Redis 滑动窗口**（项目已依赖 Redis，无新中间件）实现。新建 `app/core/ratelimit.py`：

```python
class RateLimiter:
    def __init__(self, redis, *, key_prefix: str, max_calls: int, window_seconds: int): ...

async def require_within_limit(
    request: Request,
    doctor: DoctorPrincipal = Depends(get_current_doctor),
    redis = Depends(get_redis),
) -> None:
    limiter = RateLimiter(redis, key_prefix="ratelimit:advance", max_calls=20, window_seconds=60)
    if not await limiter.allow(doctor.doctor_id):
        raise RateLimitedError(retry_after=limiter.retry_after)
```

### 2.2 限额策略

| 接口类别 | 限制 | 错误码 |
|---|---|---|
| `POST /auth/login` | 按 IP，10 次/分钟 | `429 RATE_LIMITED` |
| `POST .../advance` | 按医师，20 次/分钟 | `429 RATE_LIMITED` |
| `POST .../messages` | 按医师，60 次/分钟 | `429` |
| `GET .../stream` | 按医师，并发 5 路 | `429` / `429 CONCURRENT_LIMIT` |
| 其他写接口 | 按医师，60 次/分钟 | `429` |
| 健康检查 | **不限流** | — |

登录限流按 IP 而非 doctor_id（攻击者暴力撞库时还不知道哪个 doctor_id 存在）。其他业务按医师限流，防单医师滥用/失误循环。

### 2.3 响应头

返回标准头：`X-RateLimit-Limit` / `X-RateLimit-Remaining` / `Retry-After`。前端据此做 UI 抑制。

`429` 响应体走标准 envelope，`retryable=true`，`message="请求过于频繁，请稍后重试"`。

## 4. CORS（M2）

### 4.1 方案

新增 `CORSMiddleware`：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_allowed_origins,   # list[str]，从 env 配置
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type", "X-Request-Id", "X-Trace-Id", "X-State-Version", "Idempotency-Key"],
    max_age=600,
)
```

新增 `CORS_ALLOWED_ORIGINS` 环境变量（逗号分隔）。生产环境**禁止**使用 `["*"]`——`allow_credentials=True` 与通配 origin 是浏览器规范禁止的组合，且本系统需要 credentials。`.env.example` 默认 `http://localhost:5173`（开发）。

### 4.2 SSE 特殊处理

SSE（`EventSource`）天然不支持自定义 header，但 CORS 仍生效。确保 `allow_origins` 包含前端域名，且 SSE 响应头 `Access-Control-Allow-Credentials: true`（CORSMiddleware 会处理）。

## 5. CSRF（M3）

### 5.1 内网评估

内网部署 + token 存 sessionStorage + 同源前端，CSRF 风险有限。但 `Authorization` header 是天然 CSRF 防护（浏览器不会自动加该 header 到第三方请求），所以**只要不依赖 cookie 传 token，CSRF 基本免疫**。

### 5.2 决策

- MVP **不接 cookie**，token 走 `Authorization` header → CSRF 风险可接受，**不实现额外 CSRF token 机制**。
- 严格禁止未来把 token 切到 cookie（如要做 SSO cookie 联动，必须同时启 CSRF token）。
- 该决策写入 ADR，避免后续误改。

> 本项非加固动作，而是"显式接受风险并记录"——属于风险台账的一部分。

## 6. 模型配置白名单（M5）

### 6.1 风险

`chat_model` / `embedding_model` 当前是任意字符串。若有人篡改 `.env`，可把模型名指向攻击者控制的端点（如 `MODEL_GATEWAY_BASE_URL` 被改 + 模型名配合），导致 PHI 被发往境外。

### 6.2 方案

新增 `MODEL_WHITELIST` 环境变量（逗号分隔允许的模型名）。`ModelGatewayClient` 在构造时校验 `self._chat_model` / `self._embedding_model` ∈ 白名单，否则 fail-fast。

```python
class Settings:
    model_whitelist: list[str] = Field(default_factory=list, alias="MODEL_WHITELIST", description="允许的模型名集合")
```

白名单本身也加占位符守卫：生产环境白名单为空 → 启动失败（避免放行全部）。

### 6.3 模型网关基址锁定

`MODEL_GATEWAY_BASE_URL` 同样纳入"启动快照 + 偏离告警"（见 §7）。生产环境该值必须是预定义的内网域名集合之一。

## 7. 关键开关门禁与偏离告警（M1）

### 7.1 启动快照

应用启动时把以下"安全开关"的当前值写一条 `config.snapshot` 审计事件（持久化到 `audit_events`）：

- `app_env`
- `agent_runtime_version`
- `langgraph_public_enabled`
- `langgraph_product_ready`
- `agent_runtime_rollout_phase`
- `model_gateway_base_url`（域名部分）
- `cors_allowed_origins`

### 7.2 偏离告警

新增 `app/services/config_drift.py`，每次启动对比当前快照与上一次快照，若关键项（`langgraph_product_ready`、`rollout_phase`、`model_gateway_base_url`）发生变化，写一条 `config.drift` logger.warning + 审计事件。

这能在"误把 `XUANHU_LANGGRAPH_PRODUCT_READY=true` 推到生产"时留下不可抵赖的痕迹。

### 7.3 Prometheus 告警规则

`deploy/prometheus/rules/xuanhu-outbox-alerts.yml` 已有 outbox 告警。本阶段新增 `xuanhu-config-drift-alerts.yml`：

- `config_drift_total{type="langgraph_product_ready"} > 0` → 1h 内告警
- `production_secrets_invalid` gauge > 0 → 立即告警

## 10. 验收

- [ ] 同医师 1 分钟内调 advance 21 次 → 第 21 次返回 `429`，含 `Retry-After` 头。
- [ ] 同 IP 1 分钟内调 login 11 次 → 第 11 次 `429`。
- [ ] 生产环境 `curl /docs` → 404；`curl /openapi.json` → 404。
- [ ] 触发未捕获异常 → 客户端只收 `500 INTERNAL_ERROR` + trace_id，不含 stacktrace。
- [ ] 前端 origin 不在 `CORS_ALLOWED_ORIGINS` → 浏览器侧 CORS 拦截。
- [ ] `MODEL_WHITELIST` 为空 + 生产环境 → 启动失败。
- [ ] 修改 `langgraph_product_ready` 后重启 → `audit_events` 出现 `config.drift` 记录；Prometheus 告警触发。

## 11. 风险与回退

| 风险 | 缓解 |
|---|---|
| 限流误伤正常批量操作 | 限额基于实测调参；提供"按医师可临时提额"管理接口（MVP 可不做，运维直接改 Redis key） |
| CORS 配置遗漏前端域名导致全站跨域失败 | 灰度在预发布用真实前端域名验证；`allow_credentials=True` 与 origin 列表在 Caddy 层也校验 |
| 模型白名单阻塞合法新模型上线 | 上线流程：先改 `MODEL_WHITELIST` 环境变量再重启，文档注明 |
| config.drift 告警风暴（每次正常部署都变） | 仅对"安全开关类"变量告警；版本号等正常变更不告警 |

回退：限流可通过 `XUANHU_RATELIMIT_ENABLED` 关闭；docs 开关随 `app_env` 自动。
