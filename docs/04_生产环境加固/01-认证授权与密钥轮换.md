# 阶段 1 · API 认证授权层 + 密钥轮换

> 状态：已实施（待安全评审签字后上线）
> 上线阻断级别：**must**
> 前置依赖：无（本阶段是后续阶段的基线）
> 关联缺陷：C1 / C2 / C3 / C4 / H1

---

## 1. 目标

在不动现有 API 路径、envelope、错误码、SSE 事件 schema 的前提下，为所有 API 引入可信的医师身份，并消除客户端自报身份（`X-Doctor-Id`）这一 CRITICAL 缺陷。同时，针对 `.env` 中已泄露的真实 API Key 进行密钥轮换与历史清理。

**完成定义（Definition of Done）**：

1. 任意一个 `app/api/*.py` 路由在未携带有效 JWT 时返回 `401`，标准 envelope，错误码 `UNAUTHENTICATED`。
2. 已颁发的 JWT 中 `doctor_id` 取代客户端传入的 `X-Doctor-Id`，后者降级为"可附加可见名"，不再作为授权依据。
3. SSE 事件流（`stream_session_events`）同样要求有效 token，无效 token 时建连即断。
4. 泄露的 `MODEL_GATEWAY_API_KEY` / `EMBEDDING_GATEWAY_API_KEY` 已吊销、git 历史已清理、新 key 走密钥管理接入。
5. 新增 `app/core/auth.py` 与依赖注入，测试覆盖未授权、token 伪造、过期三种场景。

## 2. 认证方案设计：JWT + 医师身份

### 2.1 令牌模型

| 字段 | 类型 | 说明 |
|---|---|---|
| `sub` | string | 医师唯一标识（doctor_id），UUID 字符串 |
| `name` | string | 医师姓名（仅供前端展示，不作授权依据） |
| `roles` | string[] | 角色集合，MVP 阶段固定 `["doctor"]` |
| `iat` / `exp` | int | 签发 / 过期时间（Unix 秒）；MVP 有效期 8 小时 |
| `jti` | string | 令牌唯一 ID，用于吊销 |

签名算法：**HS256**（内网、单租户、无第三方签发方，对称密钥足够；如后续接入院内 SSO 可平滑迁移到 RS256）。

签名密钥来源：新增环境变量 `JWT_SIGNING_KEY`（必填，无默认值；启动时若缺失即 fail-fast）。Token 刷新 MVP 不实现——过期重新登录，降低复杂度。

### 2.2 颁发端点

新增一个**单点登录端点**（除 `/api/v1/health*` 外，唯一不需 token 的写接口）：

```
POST /api/v1/auth/login
Body: { "doctor_id": string, "password": string }
Resp: { "access_token": string, "token_type": "Bearer", "expires_in": 28800 }
```

MVP 实现细节：
- 医师账户表存于 PostgreSQL（新增 `doctors` 表：`id`, `name`, `password_hash`, `enabled`, `created_at`）。
- 密码用 `argon2id`（`argon2-cffi`）哈希存储，**禁止明文**。
- 登录失败统一返回 `401 UNAUTHENTICATED`，错误信息不区分"用户不存在"与"密码错误"。
- 连续失败 5 次锁定该账号 15 分钟（计数存 Redis，key=`auth:fail:{doctor_id}`）。

### 2.3 鉴权中间件

新建 `app/core/auth.py`，提供：

```python
async def get_current_doctor(
    authorization: str | None = Header(default=None, alias="Authorization"),
) -> DoctorPrincipal:
    """从 Bearer token 解析出可信医师主体。失败抛 UnauthenticatedError。"""
```

`DoctorPrincipal` 是一个轻量 dataclass，仅含 `doctor_id` / `name` / `roles`，**绝不携带原始 token 或密钥**。

所有现有路由的依赖注入点替换：

```python
# 改造前
doctor_id: str | None = Depends(_doctor_id),       # 客户端自报
# 改造后
doctor: DoctorPrincipal = Depends(get_current_doctor),
```

并在 handler 内用 `doctor.doctor_id` 替换原 `doctor_id` 局部变量。`_doctor_id` 依赖项保留但仅做"附加上下文"用途（如审计可见名），不参与授权。

### 2.4 SSE 鉴权

SSE 不能用普通 `Depends`（建连后才注入），改为：

1. 客户端在 query string 传 `?token=<jwt>`（仅此一处例外，SSE 浏览器无法改 header）。
2. 服务端在 `stream_session_events` 入口先 `get_current_doctor_from_query(token)` 校验，失败直接返回 `401`（不建连）。
3. 校验通过后再 `StreamingResponse`。

> 安全权衡：query string token 会进入网关访问日志。缓解措施——`token` 参数在反向代理层（阶段 3）配置 access log 脱敏，禁止记录 query string；且 token 有 8h TTL，泄露窗口有限。

### 2.5 健康检查豁免

`/api/v1/health`、`/api/v1/health/ready`、`/api/v1/health/llm`、`/api/v1/health/rag`、`/api/v1/health/outbox` 及 `/metrics/outbox` **不要求认证**——这是 K8s 探针与 Prometheus 抓取的硬约束。豁免清单在 `app/core/auth.py` 中以显式常量维护，禁止以"前缀匹配"方式豁免（避免 `/health/../` 类绕过）。

## 3. 密钥轮换方案

### 3.1 立即动作（24h 内）

1. **吊销现有泄露 key**：
   - `MODEL_GATEWAY_API_KEY=sk-c7fvhw35x...`（小米 mimo 网关）
   - `EMBEDDING_GATEWAY_API_KEY=sk-nddHCp7Tf8...`（dmxapi 网关）
   - 在各自网关后台主动吊销，生成新 key。
2. **git 历史清理**：
   ```bash
   # 用 BFG Repo-Cleaner（比 filter-branch 快且安全）
   java -jar bfg.jar --replace-text secrets.txt
   git reflog expire --expire=now --all && git gc --prune=now --aggressive
   git push --force
   ```
   `secrets.txt` 含两行旧 key 明文。
3. **`.gitleaksignore` 复查**：确认没有把这两条 key 加进忽略名单导致后续扫描漏报。若加了，删除对应行。
4. **未来防护**：在仓库根加 `.env` 的 `gitleaks` 预提交 hook，禁止再提交任何 `sk-` 开头字符串。

### 3.2 密钥管理接入

MVP 阶段不强求 Vault/KMS，但必须满足：

- 真实密钥只在**运行环境的环境变量**中存在，仓库内只有 `.env.example` 占位符。
- `.env` 文件权限收紧：`chmod 600 .env`（Linux），磁盘上明文但仅运行账户可读。
- 启动时 `safe_dump()` 已脱敏打印（现有机制保留），新增断言：若任一 `*_api_key` 仍为 `.env.example` 中的占位符值（如 `sk-change-me-to-a-real-key`），生产环境（`APP_ENV=production`）启动即 fail-fast。

### 3.3 轮换演练

上线前演练一次"零停机轮换"：通过环境变量热替换 + rolling restart，验证新旧 key 交接期间无 502。演练记录归档验收清单。

## 5. 前端联动

阶段 1 必须配套前端改动，否则前端 401 全面失效：

1. 新增登录页 `/login`，调 `POST /api/v1/auth/login`，token 存 sessionStorage（非 localStorage——降低 XSS 持久化风险）。
2. `frontend/src/api/client.ts` 在每个请求 header 注入 `Authorization: Bearer <token>`；401 时跳转登录页。
3. SSE `useSessionStream` hook 在 EventSource URL 拼 `?token=<jwt>`。
4. 移除前端对 `X-Doctor-Id` 的依赖写入（token 已含 doctor_id）。

前端改动作为阶段 1 联调的一部分，不单独立阶段。

## 6. 验收

详见 [99-验收与灰度上线.md](99-验收与灰度上线.md) 阶段 1 部分。核心断言：

- [ ] 不带 token 调任意业务路由 → `401 UNAUTHENTICATED`，envelope 结构不变。
- [ ] 带伪造签名 token → `401`，错误码 `INVALID_TOKEN`。
- [ ] 带过期 token → `401`，错误码 `TOKEN_EXPIRED`。
- [ ] SSE 不带 token 建连 → 立即 401，不产生任何事件。
- [ ] `APP_ENV=production` 且 `MODEL_GATEWAY_API_KEY` 为占位符 → 启动失败。
- [ ] git 历史中 `git log --all -p | grep -c "sk-c7fvhw35x"` 返回 0。
- [ ] 登录失败 5 次后该账号 15 分钟内不可登录。

## 7. 风险与回退

| 风险 | 缓解 |
|---|---|
| 鉴权中间件性能开销（每个请求解析 JWT） | HS256 单次校验 < 0.1ms；可接受。如需进一步优化，做 token 解析结果按 `jti` 缓存 60s（Redis） |
| 现有自动化测试因鉴权全量失败 | 提供 `tests/conftest.py` 中 `authenticated_client` fixture，自动注入测试 token；全量改造时同步更新 |
| JWT_SIGNING_KEY 丢失导致全部用户登出 | 密钥纳入密钥管理；备份两份离线副本。轮换走双密钥灰度（见附录） |
| git 历史清理 force push 影响其他开发者 | 提前通知 freeze，清理后所有人重新 clone |

回退策略：阶段 1 通过环境变量 `XUANHU_AUTH_ENABLED`（默认 `true`）控制中间件生效与否；灰度期设 `false` 可瞬间回退到无认证态，但**生产稳定后必须设回 true 并移除该开关**（避免成为永久后门）。
