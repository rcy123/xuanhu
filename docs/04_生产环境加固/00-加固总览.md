# 00 · 生产环境加固总览

> 状态：方案稿（待评审）
> 适用部署形态：**医院 / 机构内网**
> 认证方案：**JWT + 医师身份**
> 执行方式：**先写文档，再动手**

---

## 1. 背景与目标

悬壶（Xuanhu）当前处于研发基线确认阶段，已跑通问诊→辨证→开方→安全审核→医师确认→病历生成的完整闭环，但在生产环境加固维度存在系统性缺口。本组文档在不改变临床工作流契约的前提下，补齐生产环境必需的安全边界。

**核心约束**：

- 不改变已有 API 契约（路径、envelope、错误码、SSE 事件 schema）。
- 不破坏既有 LangGraph 运行时与 outbox 事件发布。
- 临床安全规则（确定性安全引擎）保持不变，加固只作用于**访问边界**与**运行态**。
- 宝贵的中医生工作流零回归：医师确认门、blocker/high 阻断、妊娠严格规则不动。

## 2. 加固范围与缺陷映射

本次审计共发现 4 类 CRITICAL、5 项 HIGH、6 项 MEDIUM 缺陷。按部署形态（内网）重新定级后，加固范围如下：

| 缺陷编号 | 严重度（内网定级） | 归档阶段 |
|---|---|---|
| C1 / C2 真实 API Key 明文泄露 | 🔴 CRITICAL | 阶段 1 |
| C3 全 API 无认证 | 🔴 CRITICAL | 阶段 1 |
| C4 X-Doctor-Id 客户端自报身份 | 🔴 CRITICAL | 阶段 1 |
| H1 SSE 事件流无认证 | 🔴 HIGH→CRITICAL（PHI 实时泄露） | 阶段 1 |
| H2 API_HOST=0.0.0.0 | 🟠 HIGH | 阶段 3 |
| H3 MinIO 默认凭据 | 🟠 HIGH | 阶段 3 |
| H4 日志/异常可能泄露敏感信息 | 🟠 HIGH | 阶段 2 |
| H5 中间件端口暴露 host | 🟠 HIGH | 阶段 3 |
| H6 无速率限制 | 🟠 HIGH | 阶段 4 |
| H7 SSE session_id 无格式校验 | 🟡 MEDIUM | 阶段 2 |
| H8 Milvus 非 TLS | 🟡 MEDIUM（内网可降级） | 阶段 3 |
| H9 /docs 无环境开关 | 🟡 MEDIUM | 阶段 4 |
| M1 langgraph_product_ready 误置 | 🟡 MEDIUM | 阶段 4 |
| M2 无 CORS 限制 | 🟡 MEDIUM（内网可降级） | 阶段 4 |
| M3 无 CSRF 保护 | 🟡 MEDIUM | 阶段 4 |
| M4 uvicorn 无 SSL | 🟡 MEDIUM（内网靠反向代理） | 阶段 3 |
| M5 模型名无白名单校验 | 🟡 MEDIUM | 阶段 4 |
| M6 错误响应暴露内部细节 | 🟡 MEDIUM | 阶段 2 |

> 内网定级说明：内网虽无公网攻击面，但**横向移动**与**院内多角色访问**仍是主要威胁。涉及 PHI 实时泄露的项（H1）在内网上调到 CRITICAL；纯公网向的项（H8/M2/M4）下调到 MEDIUM，按"可观测-即合规"原则处理。

## 4. 阶段间依赖

```
阶段1 (认证授权) ──► 阶段2 (PHI 访问控制)
        │                  │
        └──► 阶段3 (基础设施)◄─┘
                  │
                  ▼
            阶段4 (运行态安全)
                  │
                  ▼
            附录 (验收 + 灰度)
```

阶段 1 是后续所有阶段的前置：医师身份（doctor_id）必须由可信来源（JWT claim）提供，否则阶段 2 的"按医师隔离访问"无法落地。

## 5. 不在本组文档范围内

为避免范围蔓延，下列项明确不在本次加固范围，已有现成机制或属运维流程：

- **Docker 镜像漏洞扫描** — 由 CI/CD 流水线负责。
- **PostgreSQL 备份与灾难恢复** — 属 DBA 运维流程。
- **前端构建产物签名** — 由前端部署流水线负责。
- **临床安全规则本身的医学正确性** — 不属安全加固范畴，由医学审定流程负责。

## 6. 评审与生效

本组文档定稿后，需经以下角色评审签字后方可进入实施：

- 项目负责人（确认范围与上线窗口）
- 后端负责人（确认实现可行性与回归风险）
- 安全评审人（确认威胁建模与定级）

评审通过后，按"先文档、再实现、分阶段灰度"的方式推进。每个阶段独立交付、独立验收，验收清单见 [99-验收与灰度上线.md](99-验收与灰度上线.md)。
