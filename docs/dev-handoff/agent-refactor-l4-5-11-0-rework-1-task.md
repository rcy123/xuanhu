## 5. 必须修正的内容

### 5.1 EvidenceSpan 与规范化坐标

必须在以下两条路径中明确选择一条，并给出可执行示例：

- **真实等长路径**：替换结果按 Python 字符索引与原文严格等长；若用规范化 shadow 匹配，必须把命中映射回原文坐标后在原文副本上等长遮罩。禁止再把 `[REDACTED:N]` 之类标签声明为 N 字符。
- **Offset Map 路径**：明确 projection-to-source 映射的数据结构、每条 message 的稳定标识、NFKC 扩展/收缩、分隔符、越界、quote 不一致和跨消息 span 的拒绝规则。

必须包含并解释以下复验：

```powershell
$env:PYTHONUTF8='1'
uv run python -c "import unicodedata; print(len('[REDACTED:11]')); raw='体温㍑后疼痛'; print(len(raw), len(unicodedata.normalize('NFKC', raw)))"
```

不得通过“原文和投影都 NFKC”跳过原始 `EvidenceSpan` 坐标所有权。

### 5.2 有限威胁模型

- 为手机号、身份证号及明确分隔形式给出有限 grammar，而不是继续追加样例；
- 明确“同一最终请求内消息边界”如何检测和如何映射；逐条 message 扫描不能声称覆盖跨 message 重组；
- 区分实际存在的结构化身份字段和自由文本中的姓名。若没有有限姓名识别机制，将自由文本姓名明确列为残余风险/非目标，不得用不存在的结构化字段暗示已覆盖；
- 保持体温、血压、心率、血糖、日期和剂量作为负向不变量；当前 matcher 已保留这些值，不得伪造成后续先红；
- 不采用“其余连续数字全部脱敏 + 临床白名单兜底”作为默认路径。若认为必须采用，应停止并申请包含临床 owner、外部门禁和范围变更的新决策。

### 5.3 最终门禁真实边界

必须重新检查：

- `AgentRuntime._call_gateway()`；
- `ModelGatewayClient._chat_structured_impl()` 的 payload 构造；
- `_chat_structured_json_fallback()` 追加消息和直接请求；
- `_request_with_retry()` 的实际重试边界；
- `AgentRuntime` 和 `ModelGatewayClient` 的非 Intake 使用者。

方案可以选择 Runtime 门禁或 Gateway payload 门禁，但必须：

- 区分“初始 messages”与“最终 HTTP payload”；
- 证明每次实际请求都满足同一隐私不变量，或列出未覆盖路径并停止；
- 正确说明 fallback 不会重新进入 `_call_gateway()`；
- 说明共享 Runtime/Gateway 对其他 Agent 和 Legacy 的真实影响；
- 定义跨 message 的 canonical 扫描输入、边界分隔和固定脱敏失败码；
- 保留命中时零外部请求、日志/recorder 不含原始值的验收要求。

必须删除或重写当前 L4.5-11-3 的虚假先红。临床数字保留可以作为入口投影任务的负向回归；若没有新的临床规则需要制定，不应单独发布临床白名单实现任务。

- 修正姓名示例与结构化身份字段来源，保证保护声明与实际输入 schema 一致。
